ArgoniaGen: .NET 10 + Mutagen 0.54.4, the record writer of the pipeline (decision 0009): `tools/argonia_world` plans and resolves into intermediate JSON; this maps it onto Mutagen records and writes `Argonia.esm`; Spriggit 0.41.0 serialises it to `plugin/Argonia/`.

- `make plugin` runs `pipeline.py plugin`: build, `quests` and `index` scans of the masters (cached in `out/` until a plugin changes), `intermediate.py`, `generate`, Spriggit.
- The gate's `plugin-check` runs `pipeline.py check`: FormIDs append-only, pieces resolved, regenerate twice identical, `plugin/Argonia/` current, Spriggit round trip byte-identical (after `canon`, since Spriggit's deserialiser orders a group by directory listing).
- Commands: `counts`, `index`, `quests`, `generate`, `world` (see `Program.cs`). `world` (`LandWorld.cs`) writes ArgoniaWorld.esm, the generated ground (decision 0031): the WRLD from `tools/argonia_world/terrain/world.py`'s intermediate and every exterior CELL and LAND streamed from the terrain's cell lines (the contract is in `terrain/build.py`'s docstring); single-threaded, 1.08 GB peak for the whole grid; not serialised; the gate hashes a fixed cell sample against `terrain/sample-manifest.json`. Record writers so far: GLOB, MUSC, STAT, CELL (interior, with REFRs), QUST (flags, stages, VMAD object properties, event conditions), CLAS, SPEL, LVLI, and the region family in `RegionWeather.cs` (REGN, CLMT, WTHR, IMGS, the WRLD override; `world` also writes the REGN shells and each cell's XCLR from `world.json`'s `regions` and `cellRegions`, the shell pattern of `regions/api.py`); a type without a writer is an error.
- Needs `bash infra/build-vm/setup.sh` and Skyrim's Data at `$ARGONIA_GAME_ROOT/Data` (default `~/games/skyrimse/Data`). Heavy runs go under `systemd-run --user --scope -p MemoryMax=4G` (pipeline.py does this).

## The intermediate JSON contract (written by `tools/argonia_world/intermediate.py`, read by `Generate.cs`)

- Document: `{"schema": 1, "mod": "Argonia.esm", "author", "description", "loadOrder": [master file names in load order], "records": [...]}`; written with sorted keys, indent 1, so it is itself byte-stable.
- Record: `{"type": "<4-letter signature>", "formKey": "XXXXXX:Plugin.esm", "edid", "layer": "<kind>:<id>", ...fields}`. `formKey` is Mutagen's spelling; ours come from the FormID allocator (`formids.Allocator.form_key(edid, type, entity_key)`, the db's `formid` table), never invented. `"override": true` marks a record of a master (it keeps the master's FormKey). Every link field is a FormKey string; nothing is looked up by EditorID on the C# side.
- Units: positions in Skyrim units, rotations in radians (`[rx, ry, rz]`), converted in Python by `skyrim_units` only; C# does no unit maths and makes no choices.
- Order: records sorted by `TYPE_ORDER` (in `intermediate.py`) then raw FormID (master index, object id); Mutagen writes in that order, which is the canonical order the round-trip check compares. A new type adds its signature to `TYPE_ORDER`.
- Layers: a builder returns `Layer("<kind>:<id>", records)`; `compose` merges by record id (EditorID, or FormKey for overrides) in kind order `base < place < population < quest < patch`; same-kind layers may not set one field differently.
- A new record type: one writer method plus one `case "<TYPE>":` line in `Generate.Run`'s switch (in its own file, e.g. `Land*.cs` for LAND/WRLD); an unknown type is an error, never skipped. Exterior CELLs are refused by the interior writer and belong to the worldspace writer.
- PERK (`hooks_records.py`): `hidden`, `playable`, `trait`, `level`, `ranks`, `name`, `description`, `effects[{entryPoint, function: AddActivateChoice, rank, priority, tabCount, conditions[{tab, function: HasKeyword, keyword: formKey, op, value}], buttonLabel, flags[PerkScriptFlag.Flag names], fragment}]`, `fragments{script, entries[{index, name}]}` (written by `PerkRecords.cs`).
- ACTI (`life_records.py`, `ActivatorRecords.cs`): `name`, `model` (a path under Meshes, backslashes), `keywords[formKey]`, `activateTextOverride`. GMST (`"override": true` with the master's FormKey, which Python reads from the vanilla scan's `gameSettings` section `{edid: {formKey, kind}}`; a setting no master record carries is a new record of ours): `kind` (`float`, `int`, `bool`), `value`.
- PERK value entries (`combat_records.py`, 1.6 wiring): `effects[{entryPoint (a value entry point), function: MultiplyOnePlusAVMult | MultiplyAVMult (+ `actorValue`) | MultiplyValue, value, tabCount, rank, priority, conditions}]`. NPC_ and ECZN (`CombatRecords.cs`): NPC_ `name`, `race`, `template?`, `templateFlags`, `class`, `female`, `level` (fixed; calc min = max), `healthOffset`, `aggression`, `confidence`, `height`, `weight`, `perks[formKey]`, `items[{item, count}]`; ECZN `minLevel`, `maxLevel`. WEAP gains `damage`.
- Fields per type so far: GLOB `value`; MUSC `flags`; STAT `model`; CELL `name?`, `flags` (Cell.Flag names), `music?`, `lighting{ambient,directional,fogNear,fogFar: [r,g,b], ...}`, `refs[{formKey, edid?, base, pos, rot, scale?, persistent?}]`; QUST `name?`, `flags`, `priority`, `questType?`, `stages[{index, flags?}]`, `scripts[{name, properties[{name, object}]}]`, `eventConditions[{function: GetGlobalValue, global, op (CompareOperator name), value}]`; CLAS, SPEL, LVLI as in `Generate.cs`.; REGN `worldspace`, `border`, `priority`, `areas[{falloff, points}]`, `mapName?`, `weathers[{weather, chance, global?}]`, `objects[{object, density, clustering, minSlope, maxSlope, flags, radius, minHeight, maxHeight}]`; CLMT `template` (sun textures and sky model referenced from it), sun times in minutes, `volatility`, `phaseLength`, `moons`, `weathers`; WTHR `template` (cloud texture paths, precipitation, effect, sounds, sky statics, volumetric lighting, aurora and lens flare referenced from it, never its values), `colours{slot: {sunrise, day, sunset, night}}`, `ambient`, `fog`, `images`, `clouds`, `flags` and the DATA numbers; IMGS `hdr`, `cinematic`, `tint`; WRLD (override) as `terrain/world.py` plus `climate`, `music?`.
