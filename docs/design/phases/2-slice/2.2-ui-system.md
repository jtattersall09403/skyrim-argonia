# 2.2 — The UI design system and HUD

**Goal.** Morrowind's interface as if it were made today: one token set,
one component layer, one focus model that serves mouse and keyboard,
touch, and a clip-on controller equally, one Black Marsh restyle of the
Morrowind look ([0042](../../old-decisions/0042-buildout-steers-and-engineering-standards.md) §7).
Every in-game menu the slice needs is designed together as one family in
a cheap sandbox app, iterated by agents against reference images until it
meets the bars below, and the HUD and the four-window pause screen go
live in the studio and the game on real data.

## Outcome

Done. `packages/ui` holds the token set, the component layer, the focus
model and the viewport model; `apps/ui-lab` mounts every screen with
fixture data and shoots every screen, viewport and input mode in one
batch (338 shots green). The HUD, the floating prompt, the four-window
pause screen and the dev panel (opened by the backquote key or the on-screen dev chip) are live in the studio
and the game on real data; the symbol set comes from Skyrim's interface
archive and the item icons from the three.js renderer under
`tooling/ui/item-icons/`. The map ships in three styles, the chart style
with the Argonia icon set by default (owner). Deployed in Pages run
38951522627 and walked by the owner. Reports: `lanes/2.2/`.

## The look: Morrowind made today

- **Seed.** The restyled reference: dark mossy green-black panels,
  olive-bronze trim with vine and serpent corner flourishes, bone text,
  the four tiled windows (stats, magic, inventory with paperdoll, map).
  Beside it, agents gather one Morrowind screenshot per menu (UESP and
  similar) into the same folder with a one-line note each, so every
  screen has "what Morrowind did" next to "our palette". The owner adds
  any they find.
- **Font.** Pelagiad (the OpenMW free twin of Morrowind's Magic Cards,
  SIL Open Font Licence), sourced and recorded (hash, credit in the root
  README, a sourcing-register row) in the same change that adds it. Never
  the game's own font file.
- **Modern, not different.** In: crisp at any size (vector frames and
  trim, retina textures, proper type spacing and line height); quiet
  motion (fades and settles under 200 ms, bars drain smoothly, selection
  glows up, the sneak eye blinks); depth (a soft shadow under windows,
  trim catching light, the game dimmed behind an open menu). Out: blur or
  frosted glass. Living texture inside the interface (moving mist in panels,
  flickering lanterns drawn on the map) is a `P3` row, never built here;
  it is UI decoration, apart from the world's lanterns and entrance
  lights, which stand as built.
- **Bars.** Slim, in an inset trough with the trim, a soft fill with a
  little depth, a lagging ghost segment showing what was just lost;
  numbers only in the stats window, never on the HUD bar. The three
  are told apart by their fixed vertical order and colour; that is
  enough, they need no different shapes. The look leans Dark Souls more
  than Morrowind: a Morrowind–Dark Souls hybrid, never a Dark Souls copy, with one or two
  Dark Souls HUD screenshots sourced online into `research/ui/reference/`
  as inspiration beside the Morrowind ones. As in Dark Souls the bars are
  never fixed length: each grows visibly through the game as its
  governing attribute or skill rises (world/76 gives the maximum).
- **Contents are ours.** The look is copied; every window's contents come
  from our records ([world/76](../../world/76-stats-progression.md) for
  attributes, skills and bars; the item, spell and map records of their
  chunks). Spells and powers exist as in Morrowind. Breath is a HUD-only
  bar while underwater and never drains for Argonians. Climbing, boats
  and regional danger have no screen presence.
- **Ornament and symbols.** Frames, trim and flourishes from the
  reference image and the extracted Skyrim interface textures; tab, spell
  school, status, map-pin and sneak-eye symbols from Skyrim's extracted
  Flash menus, tinted bone. Item icons are rendered from each item's
  model at a fixed angle onto the slot background by a script, so every
  item ever added gets one for free. Image generation is a fallback for a
  UI piece neither source provides, never for anything else.

## a. Foundation

- `apps/ui-lab`: a Vite app whose front page lists every screen; mounts
  any screen with fixture data at any viewport and input mode; reachable
  through the tunnel like the studio. One Playwright script shoots every
  screen × viewport × input mode (mouse, touch, controller focus walk)
  into `tooling/.reports/ui-lab/` as contact sheets, and runs every
  automatic bar below, all in one batch per pass.
- `packages/ui`: tokens (colour, type, spacing, motion, the trim and
  flourish set), components (window, page, list, tabs, tooltip, slider,
  item slot and grid, bar, dialog, toast, hold-to-confirm, the floating
  prompt), one focus model (every component reachable by controller and
  finger by construction; hover-only information is a defect: tooltips
  and item stats also show on long-press and on focus), and the viewport
  model.
- **Viewports.** Three, the ones the owner plays on: desktop; phone in
  **landscape only** (844×390, the home strip and notch on the long
  edges); the unfolded Honor Magic V5 (inner 2352×2172, aspect 9.75:9,
  hinge vertical). The folded fold is a phone (about 790×350 CSS px) and
  never a separate viewport. Portrait is never designed for or shot. The
  controller is a GameSir X2s clipped to the phone, so it is tested on the
  phone and fold viewports.
- **Windows or pages.** Desktop: Morrowind's draggable, resizable
  windows. Phone: the same four windows as full-screen pages, swiped or
  tabbed. The unfolded fold is tried both ways in the
  loop and the reader's legibility and reach findings decide.
- **Controller.** The GameSir is a standard browser gamepad; the sandbox
  drives it with a scripted fake gamepad so focus walks are automatic.

## b. HUD and the prompt

- **Bars** top-left, Souls-style, in the order health, stamina, magicka;
  breath appears below them only while submerged. The bars stay as built
  (an owner ruling).
- **Vastei** (world/76 §120.3): the carried stash under the bars, a small
  plaque in the minimap's gold line, the word in small capitals and the
  whole number (owner, 2.9b). A gain, from a use or the death pile taken
  back, counts up over a second with one glint along the frame and the
  gain beside it; a death shows the loss at once. Cue `cue.hud.vastei-gain`.
- **Minimap** as in the reference; no compass. A discreet time readout,
  styled on the system, in the game as well as the studio.
- **Combat**: the target's health bar and lock-on marker. A central
  crosshair as Skyrim does it, shown while sneaking or drawing a bow
  ([2.10](2.10-stealth-crime-locks.md) § Detection feedback); no
  crosshair otherwise.
- **Sneak eye** at screen centre only while sneaking: four states
  (hidden, caution, danger, detected) per 2.10 with text and sound cue
  ids.
- **The floating prompt.** Among interactables within reach, the one
  nearest the screen centre is chosen, with hysteresis so the choice does
  not flicker between two things; it gets a faint outline glow and a
  floating button glyph for the current input (key cap, controller
  button, or a tap target on touch) with the verb beneath. Verbs come
  from the thing's record and resolve through the text catalogue (open,
  take, read, talk, search, sit, sleep, harvest, unlock…); the situation
  rewrites them (take → steal when owned by another, open → unlock when
  locked) with the crime tint. The component takes a verb id and an
  input; new verbs never touch the UI. An automatic scene (door, chest,
  item pile) tests the choice follows the camera as designed.
- **Place discovered** (owner, in this phase): Skyrim's mechanic in the
  Morrowind font. The first time the player enters a place's extent its
  record is marked discovered, a banner at the top of the screen names
  what was discovered (the place name from its record through the
  catalogue, with the place kind beneath where the record has one),
  fading in and out quietly, with a cue id for 2.14's sound. Discovery is
  per-place state in the save contract (standard 18: its home table and
  joins in world/98), and the map draws a place's marker only once it is
  discovered. The HUD component takes a place id and an input; the lift
  wires the extent test to the studio's place records.
- **Equipped hands** (owner), bottom-left as Morrowind's weapon and
  spell icons, made modern: the main hand and the off hand, each an item
  or a spell (the item icon from the renderer or the spell's school
  symbol, the name on focus or long-press), with a slim condition bar
  under an item; empty hands show nothing. Reads from the equipment and
  spell records; 2.3 and 2.9 fill it.
- **Active effects**, bottom-right as Morrowind's stack, beside the
  minimap on desktop: one symbol per effect (school or status symbol,
  tinted by kind: buff, harm, disease), stacked, with the remaining time
  as a draining ring and the name and magnitude on focus or long-press.
  2.9 fills the record; the fixture shows a stack. On a landscape phone
  the touch controls own the bottom corners, so the lane places the
  hands and the stack above them and records why.
- **Notices**: one quiet toast queue (top-centre under any banner,
  stacking, each a catalogue id with a cue id, dismissed by time or
  input; never modal) for: a skill rising ("Long Blade rose to 49"), a
  level available ("rest to level"), journal updated, quest completed, an
  item or gold gained or lost, a spell or power learned, a book read, a
  disease caught, an Owing entered, "too heavy to carry", "lock too
  hard", a save or load done. Later chunks add their notice ids to the
  catalogue; the component never changes.
- **Quick belt**: see [2.3](2.3-items-and-containers.md) decision 4.
- **Sound hooks**: every open, close, select, confirm and prompt change
  fires a named cue id that 2.14 fills. No sounds here.

## c. Screens

Every in-game menu, on fixture data, as one family: the four pause
windows (stats and level-up, magic and quick belt, inventory and
equipment, map), container and take-all, barter, dialogue, journal, rest
and wait, lockpick, death. The pause, settings, loading and landing
shells belong to Part 3 and are not shelled here.

- **Journal** is based on Morrowind's book (reference § D: dated entries,
  linked topic words, the page footer) but not a copy: restyled in the
  Black Marsh palette and made easier to navigate and to see what is
  active, with whatever interaction that needs (active quests in view
  without a detour through Options, a filter to one quest, current and
  finished told apart at a glance, jump from an entry to its topic or map
  pin, page turns by swipe, stick and wheel). The lane decides the set.
  An entry's map link exists only once its place is discovered
  ([0137](../../old-decisions/0137-directions-not-markers-until-discovered.md));
  before that the entry's directions are all the player has, and the
  fixture shows one entry each way. It must read as a **book**, a Black
  Marsh version of Morrowind's (reference § D): two leaves of aged
  page over a dark binding with a spine, corner wear, a page edge, the
  footer on the page, not a flat panel with two columns. The page and
  binding textures are the one place image generation is allowed as a
  first choice (fal, a strong model, small tiled textures, the spend
  logged) if vector and the extracted Skyrim book textures fall short;
  the lane decides.

- **Dialogue** is Morrowind's window: the speech text with hyperlinked
  words that add topics, the topic list, disposition with persuade and
  bribe, services (barter, train, travel) as buttons inside it, and the
  topic tree where asking about one thing unlocks others. The screen
  works on all three inputs; 2.5 owns the content and the dialogue
  runtime, 2.11 the quest and journal stores behind the book.
- **The map** is built three ways to exemplar quality, switchable in the
  settings, the chart style with the Argonia icon set by default (owner): (1) faithful, Morrowind's
  explored-as-you-go top-down land view in the reference palette with
  square pins and fog of war (on every map a place's pin appears only
  once the place is discovered, § b); (2) chart-style, still a top-down view in
  the window, with inked rivers, brushed marsh symbols and place names in
  the font, unexplored land blank. Land and water must read the right
  way round at a glance (filled water on blank land reads as islands):
  water is the lighter, open ground of the chart (ripple hatching or a pale wash
  fading away from the coast) and land carries the ink: a coastline
  stroke with a hachure or stipple edge on the land side, marsh symbols,
  tree and hill marks, a faint land tint; (3) faithful land with the boatable
  waterways inked over it and chart treatment where it fades into the
  unexplored. All three show tree cover (owner): the faithful land view
  as a darker canopy tone over the forested ground, the chart as tree
  marks or a canopy stipple, from the province's real vegetation
  density data (the forest and groundcover layers the studio streams),
  so a cleared marsh, a settlement and a deep forest read apart. All
  three render from the province's real terrain, water and vegetation
  data with filters and shaders, never painted. **Feature names** (owner):
  the named geography in `world/sources/hydrology/names.json` (rivers,
  water bodies, falls, peaks, passes, sea regions; 152 names) is lettered
  on every map in the chart hand, but by exposure, not discovery, since a
  river is long: a feature with a line or an area (river centrelines,
  body extents from the hydrology graph) shows its name once a fixed
  share of that geometry has been uncovered, placed along the line or
  across the area, and point features (a fall, a peak, a pass) label when
  their point is uncovered; sea regions label when any of their coast is.
  The name set and the thresholds live in the map pack, so a feature
  named later is lettered for free; all three are
  zoomable and pannable by wheel, pinch and stick on every viewport. The
  player marker on every map is Morrowind's golden dart (reference § E),
  our own vector drawing of it in the marker tan, turning with the heading.
- Every screen designs for the longest catalogue string, not the
  fixture's.

## d. Lift and the dev HUD

- The HUD and the four pause windows mount in the studio and the game
  through the 2.1 scene adapter, wired to the real character, inventory,
  equipment, stats and province map. Later chunks mount their screen the
  same way from `packages/ui`.
- The studio's dev HUD is rewritten as one coherent panel on the same
  tokens, grouped by what it does (view, time and weather, world layers,
  performance, teleport), holding every existing control
  except daylight warmth and both terrain exaggeration sliders, which are
  removed with their URL parameters. The game HUD is on by default; one
  key and one small on-screen tap target switch to the dev panel, which
  folds back to a chip. The switch and the panel work on the phone.

## Bars

Every pass measures all of these in one batch; a failure is a blocker.

1. **The look.** A fresh `reader`, shown the reference images beside the
   contact sheets, judges each screen as the reference's family and as
   "Morrowind made today" per the rules above.
2. **Nothing cut off** at any viewport, including the longest string.
3. **Readable outdoors.** Body text at or above a minimum size per
   viewport and a contrast ratio the brief fixes; the fixture includes a
   bright-daylight game frame behind the HUD.
4. **Tap sizes.** Every target at least 44 CSS px on touch viewports.
5. **Phone edges.** Nothing under the notch, the home-swipe strip or the
   fold hinge line; folding or unfolding mid-menu keeps state and layout.
6. **Three inputs.** Every action reachable by mouse and keyboard, by
   finger, and by controller focus walk; no hover-only information.
7. **Fast and light.** A menu opens within 100 ms; the HUD adds no
   measurable per-frame cost in the studio's perf panel; no animation
   runs while nothing changes; `packages/ui` has a download budget like
   the kits (standard 16).
8. **Style discipline.** A lint fails any raw colour, size or font family
   written directly into a screen; screens use tokens only.
9. **Prompt picking is never wrong** in the automatic scene.
10. **Colour is never the only signal** for any state; a fixed position
    or order counts as a signal (the three bars' vertical order is enough).
11. **Sound hooks** fire for every menu and prompt event.
12. **Every string** resolves to a text-catalogue id (the standard 4 gate).

## Loop

One pass: shoot every screen × viewport × input mode and run every
automatic bar in one batch → one reader pass over the whole grid against
the references → the parent agent judges which findings are real and
which are taste drift, diagnoses by token, component or screen → one fix
batch → re-shoot. Never one screen or one finding at a time. The parent
agent, not the reader, decides when the bar is met and stops; it reports
what it declined to change and why. Cost: minutes per pass, no GPU.

## Owner check

A walk only, no contact sheets: the studio on the phone, the fold with
the GameSir, and desktop, with the live HUD and pause screen on the
owner's character, and the sandbox for the three maps. The packet lists
one thing to try per bullet: choose the map, feel the prompt picking in a
cluttered spot, open and drag the windows, fold and unfold mid-menu, read
the bars in daylight. The owner is looking for what no bar caught.

## Polish routing

Readability, reach, cut-off and wrong-prompt failures are blockers. A
token later screens would inherit wrongly is `P1`. Living texture,
iconography refinement and motion flourishes are `P3`.

## Gotchas

- The reference is 2002 with a recolour: copy its design, not its pixel
  quality. Measure the reader against "made today", not "identical".
- Pages on phones are the same components as windows on desktop; a
  screen that forks into two implementations is a defect.
- Never ship Morrowind's or Skyrim's font or Flash files; symbols and
  textures are extracted into our own sprite sheets with their source
  recorded.
