# 2.1 — The composition seam

**Goal.** Everything the game renders and orchestrates lives in
`packages/`; `apps/world-studio` and `apps/game` compose the same packages
through different scene adapters. Done first because every later system
would otherwise be built on studio-private code and moved later.

## Outcome

Done. The runtime renderer (sky and light, water, weather, terrain
streaming, vegetation) lives in `packages/world-render`, scene
orchestration in `packages/scene` (`SceneHost` and the scene adapter),
and the save contract in `packages/save` (`SaveGame`, a per-system
registry with all-or-nothing restore). `apps/game` boots Greenspring from
those packages at `/game/` through `apps/game/src/provinceAdapter.tsx`,
with one data copy in the composed site; a CPU screenshot pair shows the
same ground and light in studio and game, differing in framing only. The
studio's own character driver (now on `PlayerMovementController`), the
world-render module state, the rain exposure seam and the game's physics
stepping are `P1` rows in the [backlog](../P-polish/backlog.md); the
studio clock is paused by default and the game runs `GAME_TIME_SCALE =
30`. Reports: `lanes/2.1/`.

## a. Extraction

- `packages/world-render`: sky, light, water, weather, terrain streaming,
  vegetation composition as **one** package first (the five-way import
  cycle splits later); every `__STUDIO_*` global resolved into one dev-only
  seam object the studio injects (standard 8).
- `packages/scene`: the §53 orchestration from the sandbox as the one
  scene adapter contract both apps implement; the sandbox composes it too
  (its gates stay green).
- Re-validate anything tuned under the paused clock at time scale 30.
- The studio's fixtures and debug layers stay in the studio
  ([0038](../../old-decisions/0038-world-build-vs-game-buildout-seam.md)); nothing is stripped in `compose.mjs`.

## b. Game boots

- `apps/game` boots the frozen province from the same packages, spawns the
  character at a slice place. No menus yet.
- `packages/save`: the versioned `SaveGame` contract (standard 17), a
  registry where each system registers its serialiser; the IndexedDB
  store, export and import, the round-trip fixture and the studio's save
  panel are 2.13's. Every later phase registers its state here on the
  day it writes it.
- The `FrameWorkQueue` hand-over budget stays the main-thread rule.

## Wide loads

The whole renderer, not the parts the slice uses: a partial extraction
leaves two renderers.

## Acceptance

- `npm run check` green; `apps/game` and the studio both render the same
  place from the same reproducible URL (studio) and spawn (game);
  screenshot pair judged identical by a `reader` (Playwright on the built
  site, CPU).
- No `__STUDIO_*` global remains in `packages/` (a grep test).
- The save contract exists as a registry each later chunk registers with
  (its round-trip test is 2.13's, when saving is built).

## Loop

None planned: the acceptance commands are the measure. If the extraction
surfaces more than five defects, run one measure–diagnose–fix pass over
them.

## Owner check

A studio URL and the game URL of the same place; "do they look the same,
and does the game load on your phone?"

## Polish routing

Renderer look differences found here are blockers if visible, else `P3`.
A `P1` row for each remaining app-private seam the extraction leaves.

## Gotchas

- The water renderer and underwater blit were app-private; 2.12 depends on
  them being in the package.
- Extract, do not improve: a visual change here cannot be told from an
  extraction defect.
