# The consistency rules

Every rule of `tools/newworld/consistency.py` (`record_check.py` runs its internal and ground families for named
places and has no rules of its own), what it compares, where each side is stored, and its pile:

- **A**: one fact that would be stored twice. It is held once and the other side is derived or enforced at its
  home, so the rule either does not exist or only guards that the derivation is fresh.
- **B**: an authored sentence restating a structured fact. The check stays; the restatement may be dropped from the
  prose when it adds nothing.
- **C**: a real judgement across domains, or a generated artefact's freshness. Stays a check, worked with the ladder
  in [consistency](consistency.md).

Tables are `newworld/story/data/db/*.jsonl`, all generated by `tools/newworld/build_db.py` from the sources named.
"Research" is `newworld/sources/research/places/*.json` (hand-authored); "map" is the extracted map
(`out/newworld/symbols.json`, `cell_region.json`, the rasters: generated from the map images).

## internal: a place record against itself

| Rule | Compares | Stored | Pile |
|---|---|---|---|
| population outside its settlement tier | `place.population` against `settlement_tier` range of the place's symbol | population: research; symbol: map (research may override) | C: an estimate against a drawn tier, two facts that must agree |
| a dead place with people | `place.status` / `place_danger.disposition_id` against population | research; danger: `place_danger.py` + owner overrules | C |
| an inhabited place with nobody | status against population | research | C |
| a friendly place gives a fight inside it | disposition against `place_give.give_kind_id` | danger; research gives | C |
| a hostile or abandoned place offers a service | disposition against gives | as above | C |
| trade with no people to keep it | population against trader gives | research | C |
| more than one treasure | treasure gives against fight gives' `reward_kind_id` | research | C |
| held_by says nobody where people live | `place.held_by` text against population | research | B: held_by is a short authored phrase, not a key |
| the words say empty where people live | summary / look note against status, population, disposition | research | B |
| the words say busy where few live | look / present note against population | research | B |
| a give the record's words never name | ore-vein give against the record's words | research | B |
| the people note's number differs from the population | number in the `people` note against population | research (3 notes carry a number, all equal now) | B |
| the words say welcoming where the place is hostile | present note against disposition | research; danger | B |
| population out of order with its peers | population against every place of the tier below | research; map | C |

## names: retired names in live files

| Rule | Compares | Stored | Pile |
|---|---|---|---|
| a retired name in a live file | every line of every live text file against each retired name's patterns, outside its allowed sense | `story/design/retired-names.json` (the one home of every retired faction, order, house, company, crew, ruling body and office name: what replaced it or that it was cut, the allowed senses, the source) | C: a name is judged in its sense (the An-Xileel as history pass, as rulers fail) |
| an owed path with no retired name left | each path on the table's owed list against what it still holds | the table's `owed` list | C (freshness): the list only shrinks |

Live is every text file of the repository except the table itself, this page, the check and its test fixtures: the
project keeps no history (owner, 2026-11-22), so a record that names a retired thing is brought current or deleted.
A line opening `>` in a phase plan is the owner's own words and is kept as written. An `owed` path still carries a
retired name and names the work that clears it (the next quest build's seed for the earlier build's plugin records);
it is reported, never failing, until that work lands, and the check then fails until the path leaves the list. A rename is one new row in the table, made in the
same commit as the grep that brings every live file to the new name.

## Names in prose

Quest records and line pages name places and people by plain name in their prose (about 3,200 mentions of 141 place
names and 980 of 13 person names across 31 files); the quest compiler has no reference token. Renames are rare:
over the history of the tables 3 places and 4 people have changed name. A token form (`{place:<id>}`) would touch
every compiler and every writer's habit for a handful of renames, so names stay plain text; a rename is a grep of
the old name across `newworld/story/quests`, `story/` and the research, made in the same commit.

## Adding a fact

Find its home first: a column or table already holding it, or the source a build derives it from. Store it there
once and derive any copy a reader needs; add a rule only for a judgement (pile C) or a sentence that restates it
(pile B).
