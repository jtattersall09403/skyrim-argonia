## Deliverables

### a. Quests as data, directions, no markers (C7)
- Quest generator: stage graphs (stages 10, 20…, onEnter actions, objectives, successors, fail-forward,
  endings) → QUST records with stages, log entries, objectives and aliases, plus generated Papyrus stage
  fragments; non-native conditions and actions call ArgoniaCore; tier protection (main > faction > side, old
  0030); nobody is unkillable (old 0138), so every quest has a fail-forward for a dead NPC.
- **Every quest anchored in the slice places is rebuilt before it is generated** (0024 §8): from its imported
  premise and cast, `quest-write` writes its record (an action plan from `action_plan.py` with the slice's other
  quests as the ledger, then truth, cast, things, clues, stages, endings, topics); a fresh `quest-reviewer`
  agent reviews it; every finding is fixed or answered in the record; `brief.py` builds its people's briefs and
  2.5's lane writes their quest topics and journal text with `dialogue-write`. Its `new` things go to the
  2.W5 builder as rows. The opening's stages are 3.3's; the rest are Part 4's (4.2, 4.3).
- **Investigation support** (decision 0025): what 0.1 §i found missing from the imported quest system for
  evidence-gated stages, presenting evidence and accusation, built whole, since the detectives' line and every
  MURDER, THEFT and FRAUD quest use it.
- **Directions generator:** quest givers' directions are written into the journal from the 2.W3 route graph
  ("follow the road west past the broken column, then take the left fork to the river"), checked by a validator
  that walks the described route in data (old 0153).
- Generated stage fragments use begin fragments only (see 2.5 §a's engine facts).
- **Grantable markers** come from the old `markers.json` registry (grantMapMarker actions, old 0137).
- **No markers:** quest targets have no map or compass markers (No Google Maps plugin; objective target data
  omitted; compass removed in 1.2); map markers for places appear only after the player reaches them on foot
  (old 0137); grantable markers only through in-world acts (a guide marks your map).
- **Acceptance:** every slice quest's record is `reviewed` with no open `quest-review` finding, and `brief.py`
  builds its briefs without refusal; its lines lint clean; each runs start to end in an L4 check; the direction
  validator passes for every direction text.

### b. Journal, world map, local map (C8, C9)
- Journal view (PrismaUI book): dated entries, quest index, topics index (every learned topic, what each NPC
  said, from ArgoniaCore's dialogue log), directions; a Black Marsh book look with ribbons and filters (old 2.2).
- World map: Flat World Map Framework with the 2.W4 painted map image; discovered markers only; no player-position
  marker unless granted.
- Local map: a PrismaUI paper-style local map from our own data (cell geometry outline, buildings, roads),
  replacing Skyrim's local map.
- **Acceptance:** L3 tests; L4 checks open each and read state.

### c. The narrative registries
- `deeds.json` (counters the condition vocabulary reads) and `rumour-pools.json` → ArgoniaCore state used by the
  2.5 evaluator.
- `markers.json` → §a's grantable markers.
- **Acceptance:** each registry has a consumer and an L1 check that every row is used; an L4 check of one rumour and
  one deed-gated line.

**Tests.** The quest, journal and directions tests are built from 0.1's test review, as in 2.5: keep tests ported,
rewrite rows rewritten to their design rule, and uncovered rules given tests, each proved to fail once on a
deliberately broken rule. The direction validator's own tests include a description that sends the player the
wrong way and must fail.

- **Joins owned:** talk → stage → journal → notice (L2, L4); stage → flag → stance → greeting (L2); complete →

  the main path and one fail-forward).
