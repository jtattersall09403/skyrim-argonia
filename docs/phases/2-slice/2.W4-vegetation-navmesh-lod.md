# 2.W4: Vegetation, navmesh and LOD

**Goal.** The marsh's plants on the ground, NPC-walkable navmesh for every exterior cell, and distant land and trees,
with the painted map image. Wide loads, each a scripted, re-runnable job.

**Starting state.** Written by the agents that close 2.W2 and 2.W3.

**Re-check before starting:** xLODGen and DynDOLOD versions and Linux/Proton reports; BM&V, Tropical Skyrim SSE and Project Rainforest versions.

**Read first.** Decisions 0009, 0010, 0014, 0022, 0026; [audit-world](../../research/2026-10-27/audit-world.md) §1, §3, §4;
[skyrim-tooling](../../research/2026-10-27/skyrim-tooling.md) §1, §5; imported `docs/design/world/00-core.md` (in
full), `20-province-design.md`, `60-water-traversal.md`, `72-navigation-ai.md`, `97-placement-principles.md`,

## Deliverables

### a. Vegetation
- Convert the flora and groundcover rules (old 0036, 0048, 0070, 0082) into: tree and shrub REFRs from
  BM&V and **Tropical Skyrim** (SSE 78044; the base-asset layer, decision 0006 §8; and Project Rainforest),
  grass through LTEX grass types using Tropical Skyrim's grass, rocks and debris REFRs; a vanilla tree, plant or
  rock is used only where neither has an equivalent.
- Density by region class with a performance budget per cell measured on the chosen GPU instance (draw calls
  and frame time), not guessed.
- **Acceptance:** frame time in the densest 10 cells stays within the G2 bar; reader panel on 20 vantage
  screenshots: no Nordic flora (pines, snow, heather) anywhere.

### b. Navmesh
- The production version of G4's route for every exterior cell and interior: **tes4skyrim's navmesh method**
  (decision 0026 §3), generating walkable triangles from the world's collision, with door triangles linked to
  load doors, water triangles flagged, cross-cell edge links, NAVI master data, and cover data where cheap.
- The Creation Kit's generator (decision 0018), scripted on the Windows game machine, is the check on a sample
  and covers any cell the generator cannot, with its output captured to Spriggit.
- **Acceptance:** 200 random NPC path requests between reachable points succeed (bridge path query); 20 NPCs
  with sandbox packages do not stand still for more than 60 s in a 10-minute sim.

### c. LOD and the world map image
- xLODGen (terrain LOD) and DynDOLOD (object and tree LOD) under Wine with the documented Texconv workaround
  (plain Wine 9.22, retries); 32–64 GB RAM advised, so run on a temporary 64 GiB spot instance (budget in decision
  0008), stopped after.
- **Who generates LOD (decision 0014 §4):** LOD output is derived from mod and vanilla textures, so it is never
  shipped. Measure the player-side cost (time, RAM) of the same steps; the installer runs terrain LOD always and
  object LOD only if a typical player PC (16 GB) can do it in under an hour; otherwise ship our LOD settings only
  and record the visual loss for players (the owner's GPU box gets full LOD).
- A painted-look world map image rendered from our own heightfield, hydrology and land cover (the UI
  exception), consumed by the paper map (2.12) and the studio panel's map (0.4).
- **Acceptance:** distant views show terrain and tree LOD with no missing tiles; the LOD build is a scripted job.

## Loops (docs/loops.md)
- **Subsets:** vegetation by region class (L4 stills plus frame time); navmesh (L4 `nav` queries); LOD (L4 vantage
  stills).
- **Joins owned:** navmesh ↔ doors and water (L4 `nav` through a door and along a bank); near ↔ LOD hand-off (**L5,
  reason: pop-in shows only in motion**).
- **Journeys:** none (no system state).

## Risks and fallbacks
- **Navmesh scale-up** breaks on cases the sample did not have (cliffs, docks, water): survey all failures first,
  fix in one batch; the CK on the Windows game machine for residual cells.
- **Too many objects** for Skyrim's cell budgets in dense jungle: thin by region class; move density into grass and
  LOD.

## Deliberately out of scope
Place-level dressing (2.W5); the final look (4.6).
