# 0.1: Bootstrap the repo, the ways of working, the build VM and the content

**Goal.** A planner session on the build VM can brief agents that build, check and commit safely. The
toolchain the later chunks need is installed and smoke-tested, the old project's content is imported and
validates, and the owner has had the first check-in.

**Starting state.** 0.0 passed (G0): the GPU box exists, vanilla Skyrim streams, and the owner has the IAM
policy and quota in place. The repo holds docs only: this plan, decisions, research, owner brief and accounting.
The owner has an AWS budget alert, an `argonia-build` m7i.xlarge spot instance (Ubuntu 24.04, 120 GiB gp3, no
inbound rules, SSM role `argonia-build-ssm`), a VS Code tunnel `argonia-build` reachable at
vscode.dev/tunnel/argonia-build, Claude Code logged in, `gh` authenticated, and the repo cloned to
`~/skyrim-argonia`. If any of that is missing, the first check-in asks for it.

**Re-check before starting:** Claude Code install method, Ghidra/JDK versions, .NET/Mutagen/Spriggit versions,
m7i.xlarge spot price.

### c. The no-assets guard and the gate
- `tooling/guards/no_assets.py` (decision 0003): refuses staged files by extension, by magic bytes (NIF
  "Gamebryo File Format", BSA "BSA\0", DDS "DDS ", HKX packfile, FSB/XWM/FUZ, TES4 "TES4" record header, FromSoft
  "BND4"/"DCX\0"), over 1 MB outside `tooling/guards/allowlist.txt`, and text containing decompiler signatures
  (`undefined8`, `__thiscall`, `FUN_`, `DAT_`, Ghidra/IDA banners). Installed as a git pre-commit hook and run
  in the gate.
- **The gate:** `make check` runs, in parallel, in ≤ 3 minutes: no-assets guard over the tree, Python lint
  and unit tests, C++ core unit tests (once they exist), UI harness tests (once they exist), Spriggit
  round-trip (once it exists), schema validation of `world/` and `data/`, CLAUDE.md word budget, link check of
  `docs/`. One command, one summary of every red. CI (GitHub Actions, free for public repos) runs the same
  command on push.
- **Acceptance:** committing a 1-byte file named `x.nif` or a file starting with `TES4` is refused; `make check`
  passes on a clean tree and lists every red on a seeded-bad tree.

- Node 22, Chrome for Testing (headless), Playwright: the PrismaUI view harness (L3).

- `tools/import_old.py --commit <sha>` copies the paths in [source-map.md](../../source-map.md) §1 into `world/`

- **The old rule packages, for G10** (read-only reference, `private/old-packages/`, never built into anything
  until G10 decides): `packages/dialogue`, `narrative`, `economy`, `crafting`, `save`, `magic`, `world-time`,
  `text-catalogue`, and the non-render folders of `packages/game-core/src` (`stats`, `crime`, `factions`,
  `inventory`, `equipment`, `scheduling`, `perception`, `traps`, `travel`, `encounters`, `people`, `rng`,
  `validation`) with their tests. Measured at writing: dialogue ~3,000 lines, narrative ~2,200, stats ~5,000,
  economy ~1,000, crafting ~1,300, save ~1,400, with hundreds of tests. **Never** `combat`, `ai`, `anim`,
  `movement`, `locomotion` or any render folder (decision 0019).
- **The review of the old dialogue and quest tests** (owner: "a lot of them, but not all, are bad"). About 78 test
  files in the old repo touch dialogue, topics, quests, journal and directions: the `packages/dialogue` and
  `packages/narrative` tests, the headless walkers and drivers, and the Python gates in `tooling/`. A `research`
  agent reads each one against the design docs, which are the specification
  (`docs/design/quests/85-condition-vocabulary.md`, the dialogue standards and culture sheets, `quests/80`,
  `00-overview`, old 0137, 0139, 0143, 0145 and 0153). It classifies every test:
  - **keep:** it asserts a rule the design states, in the design's terms, and it would fail if that rule broke
    (proved by breaking the rule once);
  - **rewrite:** the intent is right but the assertion is wrong, weak or brittle. Examples: a snapshot of a whole
    output, a count that would pass on wrong content, a check of an implementation detail, a test that restates
    its own fixture;
  - **drop:** it tests the old harness, a three.js or React detail, or a behaviour the design no longer wants.

  Where a test and the design disagree, the design wins unless the owner rules otherwise (listed for the owner
  as a short table). The output is `docs/research/old-tests/dialogue-quests.md`: one row per test, with its
  verdict, the design line it serves and the rule it should assert. It also lists the design rules no test
  covers. 2.5 and 2.12 build their test suites from this table, not from the old files, and G10 measures only the
  tests marked keep.
- **The old polish backlog** (`docs/phases/P-polish/backlog.md`, ~470 rows): each row is carried into
  `docs/phases/backlog.md` with the chunk that owns it (if it states a design intent still true here) or dropped
  with a one-word reason (three.js-specific). Find everything once, so no later brief re-reads the old backlog.
- **Acceptance:** integrity check passes on the imported copy; `docs/design/` link check passes; every old

## Loops (docs/loops.md)
None: tooling chunks run their acceptance commands and the gate, and prove each hook on a fail-on-purpose case.

## Exit gate
- `make check` green in CI and on the VM; every hook's fail-on-purpose test passes.
- Toolchain smoke green; game files present; world imported and valid.
- PROGRESS row for 0.1 done; 0.2's Starting state written.

## Risks and fallbacks
- **Wine/msvc-wine install friction**: fall back to clang-cl + xwin (route b) and leave msvc-wine to 0.2 G1.
- **Steam Guard from a datacentre IP** prompts repeatedly: use `steamcmd` with the owner's mobile approval;
  if it keeps failing, the owner copies the files once from their own install via the stream later.
- **R2 credentials lost**: the heightfield can be rebuilt by the old repo's terrain chain from the vault, but
  the vault itself lives in R2; if both are gone, re-derive from Tamriel Worldspaces – Argonia (118678) with the
  old chain (expensive; owner call).

## Deliberately out of scope
The GPU box (0.2), any game-facing code (0.2 onwards), CI on a GPU (never: GPU checks are L4 jobs on the GPU box).
