### c. The no-assets guard and the gate
- `tooling/guards/no_assets.py` (decision 0003): refuses staged files by extension, by magic bytes (NIF
  "Gamebryo File Format", BSA "BSA\0", DDS "DDS ", HKX packfile, FSB/XWM/FUZ, TES4 "TES4" record header, FromSoft
  "BND4"/"DCX\0"), over 1 MB outside `tooling/guards/allowlist.txt`, and text containing decompiler signatures
  (`undefined8`, `__thiscall`, `FUN_`, `DAT_`, Ghidra/IDA banners). Installed as a git pre-commit hook and run
  in the gate.
- **The gate:** `make check` runs, in parallel, in ≤ 3 minutes: no-assets guard over the tree, Python lint
  and unit tests, C++ core unit tests (once they exist), UI harness tests (once they exist), Spriggit
  round-trip (once it exists), schema validation of `world/` and `data/`, CLAUDE.md word budget, link check of
  `docs/`. One command, one summary of every red. CI (GitHub Actions, free for public repos) runs the same
  command on push.
- **Acceptance:** committing a 1-byte file named `x.nif` or a file starting with `TES4` is refused; `make check`
  passes on a clean tree and lists every red on a seeded-bad tree.

### j. The build-versus-reuse audit (owner ruling, 2026-10-28)
Before any planned component is built, search for an existing tool, mod or open code that already does it. One
audit covers every component in PLAN §4's table, written to `docs/research/reuse-audit.md`. Each row gives a
verdict (use as a dependency, fork, port the method, or build) with the licence, the supported runtime, the
maturity and file:line evidence. Every later brief then names its prior art and does a short re-check of it.

**tes4skyrim** (`bryantmh/tes4skyrim`, MIT, with its GPL-3 OpenMW parts kept in separate DLLs; built for Skyrim
1.6.1170, 1.6.659 and 1.5.97) is read in full first. It converts whole TES games to Skyrim, so much of what we
plan already exists there:
- **`tes_runtime/morrowind/` (MorrowindRuntime.dll):** a port of OpenMW's dialogue engine and MWScript
  interpreter into an SKSE plugin. It provides:
  - the topic list, hyperlinked keywords, history, disposition and persuasion (admire, intimidate, taunt, bribe);
  - services (travel, trade through Skyrim's barter menu, enchanting), quests and the journal;
  - crime through Skyrim's crime system, scripts on objects;
  - an optional Morrowind character sheet and level-up screen that raises attributes;
  - its own co-save (`MWRT`) and headless store, filter and script tests.

  This is most of what G5, 1.3, 2.5, 2.6 and 2.12 plan to build. The audit asks:
  - can our dialogue and quest data be compiled into its sidecar shape (TES3-style topics and responses with

## Loops (docs/loops.md)
None: tooling chunks run their acceptance commands and the gate, and prove each hook on a fail-on-purpose case.

## Exit gate
- `make check` green in CI and on the VM; every hook's fail-on-purpose test passes.
- Toolchain smoke green; game files present; world imported and valid.
- The writing skills' acceptance (§b) green; §i closed, or running as its side lane with 1.3 named as its
  deadline.
- PROGRESS row for 0.1 done; 0.2's Starting state written.

## Risks and fallbacks
- **Wine/msvc-wine install friction**: fall back to clang-cl + xwin (route b) and leave msvc-wine to 0.2 G1.
- **Steam Guard from a datacentre IP** prompts repeatedly: use `steamcmd` with the owner's mobile approval;
  if it keeps failing, the owner copies the files once from their own install via the stream later.
- **R2 credentials lost**: the heightfield can be rebuilt by the old repo's terrain chain from the vault, but
  the vault itself lives in R2; if both are gone, re-derive from Tamriel Worldspaces – Argonia (118678) with the
  old chain (expensive; owner call).

The GPU box (0.2), any game-facing code (0.2 onwards), CI on a GPU (never: GPU checks are L4 jobs on the GPU box).
