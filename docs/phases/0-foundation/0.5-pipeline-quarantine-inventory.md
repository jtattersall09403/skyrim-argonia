# 0.5: The record pipeline, the vanilla quarantine and the immersion inventory

**Goal.** Records are generated, never hand-made: world JSON → Python tools → ArgoniaGen (C#, Mutagen) →
Spriggit YAML → `Argonia.esm`, deterministic and reviewable. A new game no longer runs Skyrim, and the immersion
inventory lists every element a player could meet.

**Starting state.** G4 passed: terrain, one place, navmesh and faces generated for the Claywater Station block,
with spike code in `spikes/s4/`. The kit-id mapper exists in spike form.

**Re-check before starting:** Mutagen and Spriggit versions; russo-2025/papyrus-compiler status.

**Read first.** Decisions 0003, 0006, 0009, 0012, 0014, 0018; [source-map.md](../../source-map.md);
[audit-world](../../research/2026-10-27/audit-world.md) §1.

## Deliverables

### a. The generation pipeline
- `tools/argonia_world` (Python package): loaders for every imported schema, the units module
  (`skyrim_units.py`), the FormID allocator (`data/formids.json`, append-only), the **kit-id mapper**
  (`kit_to_base.py` from G4, production quality: every kit piece and composite in the old manifests resolves to a
  base record or a new STAT of ours; an L1 check fails on any unresolved layout op), intermediate JSON writers.
- `tools/ArgoniaGen` (C#): reads intermediate JSON, writes records with Mutagen into `Argonia.esm` (ESM flag;
  split into ESL-flagged helpers only if record counts require), then Spriggit serialize to `plugin/`.
- `make plugin` regenerates deterministically; `make check` includes a Spriggit round trip
  (serialize → deserialize → byte-identical plugin) and "regenerate twice, no diff".
- Papyrus build: the reference compiler (the Creation Kit's PapyrusCompiler under Wine) with the base script
  sources from the CK's `Scripts.zip` (never committed; decision 0018); compare russo-2025/papyrus-compiler as a native option.
- **CK load check:** `tools/ck/load_check.sh` loads `Argonia.esm` in the CK under Wine/Xvfb and fails on new
  warnings in its log (an extra L1 check; decision 0018).
- BSA packing with BSArch under Wine (our files only: UI images, fonts, Papyrus `.pex`, our textures if any).
- **Layers by record id** (old 0140): a place, a population, a quest or a patch is a layer over generated base
  records, applied by id; regenerating the base never drops a layer, and a layer never edits another's records.
- **Acceptance:** `make plugin && make check` green; an intentional record change shows up as a one-file
  Spriggit diff; the G4 block, the proving ground and the booth regenerate from the pipeline (not spike code)
  with no diff on a second run.

- **Minimal sheet records for the studio character:** one Argonian race package, one class, one birthsign and one
  start kit, generated from the imported data so 0.4's base save is built from real records. 2.1 fills the rest.

### b. Vanilla quarantine baseline (decision 0012)
- Our start quest: new game → a black screen → Argonia's opening cell (a placeholder in the Claywater Station block until 3.3 builds the opening);
  MQ101 and every start-game-enabled vanilla quest prevented; dragons, word walls and shouts removed from the
  player's world; the Tamriel worldspace unreachable.
- A scene and journey: list running quests after a new game and after 1, 10 and 50 in-game days (time skipped through the
  bridge); compare with `data/quarantine/allowed-quests.json`.
- **Acceptance:** the journey passes on the game runner (until 0.4 lands, as a G1-bridge script); no vanilla music plays (bridge reads the music type).

### c. The immersion inventory v1
- `tools/immersion/inventory.py`: enumerates every record type listed in decision 0006 §1 across our load
  order (Mutagen over the masters and dependencies), every vanilla menu SWF in the stack, every PrismaUI view,
  every music/sound record, every GMST/string; computes reachability from our world (placed, sold, levelled
  lists, spawns, menus); writes `data/immersion/inventory.jsonl`.
- Verdicts start as `unreviewed`; the gate reports counts through Part 1 and fails on any reachable `unreviewed`
  row from Part 2's close (2.17) on; every Part 4 packet's elements enter compliant (decision 0023 §6).
- **Acceptance:** the inventory lists every vanilla menu and every record our sample world references; counts
  by type are in PROGRESS.

## Loops (docs/loops.md)
None (a tooling chunk): pipeline determinism and the Spriggit round trip at L1; the quarantine journey on the
game runner; inventory counts at L1.

## Done when
`make plugin && make check` green with the round trip and the no-diff rerun; the CK load check clean; the
quarantine journey green at 1, 10 and 50 days; the inventory v1 written with counts in PROGRESS.

## Risks and fallbacks
- **Record counts outgrow one ESM** (FormID limits): split into ESL-flagged helpers by kind, decided by a measured
  count, not in advance.
- **The CK under Wine is flaky** for the load check: keep the check advisory until it is stable twice in a row,
  then gate on it.

## Deliberately out of scope
World content beyond the G4 block and the fixtures (the world track 2.W); the full quarantine of every vanilla
system (closed per system as Part 2 replaces it, finished in 2.17).
