# 0.4: The pipeline, the quarantine, the immersion inventory and the first block

**Goal.** Records are generated, never hand-made: world JSON → `tools/argonia_world` → `tools/ArgoniaGen`
(Mutagen) → Spriggit YAML → `Argonia.esm`, deterministic and reviewable. A new game no longer runs Skyrim. The
immersion inventory lists every element a player could meet. And the first block of the province, Claywater
Station's 8×8 cells, is built the native way (decisions 0026, 0028) and walked in game: the land from the pulled
heightfield with Tropical Skyrim's textures and grass, one region's trees and rocks through the CK's generator,
the place as references on its own ground, three people with whole-body templates, navmesh. Part 1 builds its
systems on this block; the world track (2.W1) starts from this pipeline.

**Starting state (2026-10-29).** `tools/ArgoniaGen` reads `Skyrim.esm` (0.1); the 21 schemas and the integrity
checker are in `world/schemas/` and `tools/argonia_world/` (0 errors); the five frozen arrays are in
`$ARGONIA_DATA`, hash-verified; the imported world holds Claywater Station's design, layout (a guide), people and
facts; `freeze.json`, the terrain patches and the hydrology graph are in `world/sources/`. §a–§c run on the build
VM from now; §d needs 0.2's profile (Tropical Skyrim loaded) and 0.3's hands.

**Read first.** Decisions 0003, 0006, 0009, 0012, 0014, 0018, 0026, 0028; [source-map.md](../../source-map.md);
[prior-art-world-to-skyrim](../../research/2026-10-28/prior-art-world-to-skyrim.md); the reuse audit's navmesh and
Mutagen rows; imported `docs/design/world/98-data-model.md`, `97-placement-principles.md`, the Claywater design
note; universal-modder's field note on generating plugin records from Python (0020 §4).

## Deliverables

### 0. The data model (decision 0030), before anything reads the world
- `world/schema.sql`: the relational schema of the whole world in third normal form (one table per entity and
  relationship, primary and foreign keys, lookup tables for enumerations, `CHECK` constraints, a comment per
  table saying what it is the home of), designed for every family the plan names, Part 1's in full and the rest
  at least as tables with their keys. `docs/design/world/98-data-model.md` rewritten as the schema's guide.
- `tools/argonia_world/db.py`: loads `world/db/*.jsonl` into SQLite with the DDL and foreign keys on, exposes
  queries and typed rows, and is the only write path (writes land back in the JSONL tables sorted by key);
  `make db` builds `out/world.sqlite` for DuckDB or pandas; the load with its constraints is the integrity gate,
  plus named checks for the rules SQL cannot state.
- **Migrate Part 1's families** from `world/sources/` into tables: places and their sockets, people and
  factions, items and locks, quests (stages, objectives, cast knowledge, things, clues, actions, endings), topics
  and lines, facts and culture, routes, the sheet's tables, the FormID table; delete each migrated file from
  `world/sources/` (`IMPORTED_FROM.md` stays as provenance). The rest migrates with the chunk that first reads it.
- **Repoint the writing skills:** the quest record is rows; `brief.py`, `place_brief.py`, `quest-review` and
  `dialogue-write` read and write through `db.py`; the condition vocabulary is a lookup table. LH38 and MR01
  go record → briefs again from the database with no hand fixes.
- **Acceptance:** the load with foreign keys on passes; a row with a dangling key is refused; `make check` stays
  under its limit with every table duplicated tenfold (the scale measurement); the two quests' briefs match the
  pre-migration ones; no tool under `tools/` or `.claude/` opens a `world/` file directly (a grep in the gate).

### a. The generation pipeline
- `tools/argonia_world`: loaders for every imported schema; the **units module** (`skyrim_units.py`, the only
  place Skyrim unit facts live); the **FormID allocator** (`data/formids.json`, append-only); the **piece
  resolver** (`pieces.py`: an old kit id or mesh path → source plugin and base record, read from the synced
  dependency plugins; a mesh with no base record → a new STAT of ours; an L1 check fails on any unresolved piece
  a place's design uses); intermediate JSON writers.
- `tools/ArgoniaGen`: reads intermediate JSON, writes records with Mutagen into `Argonia.esm` (masters: the
  dependency plugins 0.2 synced; ESL-flagged helpers only if a measured count requires), then Spriggit to
  `plugin/`.
- `make plugin` regenerates deterministically; `make check` gains the Spriggit round trip (serialize →
  deserialize → byte-identical) and "regenerate twice, no diff".
- Papyrus: the CK's compiler on the game machine with the base sources from `Scripts.zip` (never committed),
  driven by `run.sh`; russo-2025/papyrus-compiler compared as a native option.
- **The CK load check** (advisory until stable twice): `Argonia.esm` loaded in the CK on the game machine,
  scripted; new warnings fail.
- BSA packing with BSArch on the game machine (our files only).
- **Layers by record id** (old 0140): a place, a population, a quest or a patch is a layer over generated base
  records; regenerating the base never drops a layer.
- **Minimal sheet records for the studio character:** one Argonian race package, one class, one birthsign, one
  start kit, from the imported data (2.1 fills the rest).
- **Acceptance:** `make plugin && make check` green; an intentional record change is a one-file Spriggit diff;
  no diff on a second run.

### b. The vanilla quarantine (decision 0012)
- Our start quest: new game → black screen → the block's holding cell (3.3 builds the opening); MQ101 and every
  start-game-enabled vanilla quest prevented; dragons, word walls and shouts removed from the player's world; the
  Tamriel worldspace unreachable; no vanilla music.
- A journey (0.3's runner): list running quests after a new game and after 1, 10 and 50 in-game days against
  `data/quarantine/allowed-quests.json`; the music type read.
- **Acceptance:** the journey green at all three skips.

### c. The immersion inventory v1 (decision 0006)
- `tools/immersion/inventory.py`: every record type 0006 §1 lists across our load order (Mutagen over the masters
  and dependencies), every vanilla menu SWF in the profile, every view of ours, every music and sound record,
  every GMST and string; reachability from our world; `data/immersion/inventory.jsonl`, verdicts `unreviewed`.
  The gate reports counts through Part 1 and fails on a reachable `unreviewed` row from 2.17.
- **Acceptance:** the inventory lists every vanilla menu and every record the block references.

### d. The first block: Claywater Station, the native way
- **Terrain:** the block's cells as LAND from `refined-height-frozen-f32.npy` (VHGT offsets and deltas, VNML,
  VCLR), its land-cover classes painted as the vanilla LTEX forms Tropical Skyrim replaces (0028); grass then
  appears by itself in game.
- **The region:** one REGN for the block's ecological class with its object list (vanilla tree, shrub, rock and
  flora forms; density, slope and height bands, water avoidance from the imported flora rules) and its weather
  list over Tropical Skyrim's weathers; the CK's region generator run on it, scripted on the game machine; the
  generated REFRs reviewed as a diff.
- **Water:** the block's reach as cell water heights and placed vanilla pieces from the hydrology graph (the
  stepped-river method is 2.W2's first step; here, flat water at the graph's level is enough).
- **The place:** buildings, props, doors, containers, beds and markers as REFRs of the Black Marsh mods' base
  records on direct landscape edits owned by the place's layer (0026 §3), positioned from the design note with
  the old layout as a guide; load doors to their interiors.
- **People:** three Claywater people from the imported records with whole-body templates (TPLT, traits flag;
  Argonian heads the critical case), a sandbox package by day and a sleep package by night.
- **Navmesh:** (a) one CK navmesh round-tripped through Mutagen, an NPC walks it; (b) our DotRecast job over the
  placed meshes' collision, written in tes4skyrim's documented binary shape (NVNM, NAVI, edge links, door
  triangles; 0026 §4); (c) the CK's generator, scripted, as the check and fallback.
- **The fixtures:** the proving ground and the booth (0.3 §c), generated here.
- **The look loop:** vantage stills through the bridge, read by a `reader` against the design note with the
  Nordic-tells checklist; fix and re-shoot until they match.
- **Acceptance (in game, from `bat claywater`):** the player walks the road into the place and into an interior;
  ground heights match the heightfield within 0.5 m at sampled points away from the place's own edits; grass
  shows on the painted ground; the region's trees stand where the generator put them; the three people path
  between two spots and sleep at night; each person's full-body still shows no seam, tone mismatch or dark face;
  every piece the design uses resolves; the reader passes the stills; regenerating twice gives identical YAML.

## Risks and fallbacks
- **Navmesh unsolved by (a)–(c):** the CK's generator alone for Part 1, our job revisited in 2.W4 with the
  measured failure.
- **A unique Argonian face no template covers:** the CK's FaceGen export, development and the owner's machine
  only, and the installer design of 0014 §3.
- **The region generator cannot be driven headless:** the CK scripted through its own command line and a
  prepared layout; else our own placement from the same region rules, writing the same REFRs (the rules stay
  the data).
- **Record counts outgrow one ESM:** ESL-flagged helpers by kind, decided by a measured count.

## Deliberately out of scope
Any system on the block (Part 1); the rest of the province (2.W1 onwards); the opening (3.3).
