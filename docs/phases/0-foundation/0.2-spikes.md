# 0.2: The GPU box and ten go/no-go spikes

**Goal.** Prove, on samples, every assumption the architecture rests on before building on it. Each spike has a
gate (G1–G11) with a pass condition, a time budget (working days of lane time), listed workarounds and a
consequence if it fails. Spike code lives in `spikes/<id>/` unless the spike says its output becomes the real
component.

**Starting state.** 0.1 done: toolchain, guards, gate, world, the goals list and the reuse audit ready, game files on the
build VM.

**Re-check before starting:** Skyrim's current Steam version and SKSE builds (silverlock), the Address Library
version, each candidate mod's latest file and supported runtimes, Proton and Selkies versions, GPU spot prices in
eu-west-2. Record what changed in `docs/research/`.

**Read first.** Decisions 0001, 0002, 0004, 0007, 0008, 0010, 0014, 0020; universal-modder's `game-recon`,
`game-automation` and `reverse-engineering` skills and the field notes listed in 0020 §4 for S1 (command-file
bridge, frame readback, unkillable-zombie relaunch), S4 (plugin record format), S6 (DSR proxy-DLL note); research
[skyrim-tooling](../../research/2026-10-27/skyrim-tooling.md) (§0–3, §5–7),
[skyrim-morrowind-soul](../../research/2026-10-27/skyrim-morrowind-soul.md) §1, §5,
[skyrim-combat-traversal](../../research/2026-10-27/skyrim-combat-traversal.md) §0–1, §4,
[um-ghidra-lens](../../research/2026-10-27/um-ghidra-lens.md) §3A, §1.3–1.4,
[hosting-streaming](../../research/2026-10-27/hosting-streaming.md).

**Order and dependencies.** G0 (0.0) has passed and the GPU box exists. **S1** (bridge) while the build-VM-side
spikes **S4** and **S6** run in parallel. **S3** needs S1's bridge with its input endpoint. **S2**, **S5**, **S7** and
**S9** need S3's stack. **S10** needs S1 and S5 (it runs on the build VM first, then in game). **S8** composes
everything and runs last. With the 5x plan run at most two lanes at once,
and only one lane drives the GPU box at a time (`job_guard.sh --gpu`).

## S0: The GPU box
Built in [0.0](0.0-can-it-be-played.md) (G0). Here it gains Crash Logger SSE, the aws cli for save backup, and
the idle-stop rule extended to "no stream client and no GPU lock held". Dark Souls Remastered is installed on it
for G6.

## S1 → G1: SKSE plugin built on Linux, loading under Proton, with a minimal agent bridge (budget 6 days)
- Build a hello-world CommonLibSSE-NG plugin from the build VM: route (a) msvc-wine (`cl`/`link` under Wine,
  CMake + Ninja, vcpkg cross triplet); if blocked, route (b) clang-cl + xwin + **MSVC `link.exe`** (NG's wiki:
  `lld-link` loses the exports), or explicit `.def` exports with lld-link. Address Library for the candidate
  runtime(s).
- The plugin is the seed of `ArgoniaBridge`. It binds an HTTP server to **127.0.0.1 only** on the GPU box, with a
  per-boot token; the build VM reaches it through an SSH tunnel (`ssh -L`), never over an open port. Endpoints:
  `/ping`, `/console` (a console command on the main thread via the SKSE task interface), `/teleport`
  (`coc`/`setpos`), `/state` (position, cell, frame counter), `/screenshot` (D3D11 backbuffer copy → PNG + hash),
  `/input` (queue keyboard/gamepad events: move, attack, block, dodge, activate, menu). Patterns: SkyrimNet's MCP
  server; universal-modder's command-file bridge as the fallback.
- Launch `skse64_loader.exe` under Proton directly (no launcher, `SteamAppId=489830`, ini files pre-written),
  with `plugins.txt`/`loadorder.txt` written by script (no MO2).
- A minimal `make deploy` (rsync the built DLL/plugin to the box, restart the game, wait for `/ping`).
- **G1 passes when:** from the build VM, a script starts the GPU box, deploys, launches the game to a test cell,
  calls every endpoint (an `/input` walk changes `/state` position), gets two screenshots whose hashes differ while
  the camera turns, and stops the box, with no human action.
- **If it fails:** try both build routes and two Proton versions; then a temporary Windows spot instance (costed
  first, within Part 0's budget in decision 0008) to separate "build" from "run". If running under Proton is the
  failure, decision 0001's fallback applies (owner re-plan).

## S2 → G2: Performance with the full stack (budget 2 days)
- 0.0 settled the stream, the controls, the latency and readability on vanilla Skyrim. G2 re-measures with the
  S3 stack and our kind of scene: dense Tropical Skyrim and BM&V trees, water, 10 NPCs.
- Benchmark 1080p frame times on g6.xlarge (L4), g4dn.xlarge (T4) and g5.xlarge (A10G) with Community Shaders on
  and off: median and 1% lows, CPU vs GPU bound (Skyrim is often CPU-bound on cloud Xeons). Re-measure the
  latency sum of 0.0 with the stack loaded.
- **G2 passes when:** one instance type holds ≥ 60 fps median and ≥ 45 fps 1% lows in the scene within budget,
  and the latency sum is within 10 ms of 0.0's. Record the instance, codec, bitrate, UI scale and per-hour cost in
  `infra/README.md` and decision 0007. The latency sum is written beside every later feel verdict (1.6, 2.7), so
  DS1 windows are never retuned to suit a laggy stream; any latency compensation is an owner ruling, recorded as
  a deviation.
- **If it fails:** lighter shader settings; thin the scene's density (a world-track input, 2.W4); a larger
  instance.

## S4 → G4: Claywater Station built natively, the Skyrim way (decision 0026)
Sample: the 8×8-cell block holding **Claywater Station** (owner-accepted in the old repo) and its road. This block
becomes Part 1's place, so it is built to keep. It is rebuilt natively from its design, never converted from the
old layout's 381 ops; the old layout is a guide to positions only.

Tools, used in this order of preference: Mutagen (records), tes4skyrim (navmesh, records, LOD; MIT, build on it,
do not start from scratch), DotRecast, houseCARL (load order and conflicts), SkyLink AI (in-game stills, state and
console; development only, never redistributed), the Creation Kit on the Windows game machine (check and fallback).
Read `docs/research/2026-10-28/prior-art-world-to-skyrim.md` first.

- **Terrain:** heightfield → LAND (VHGT offsets plus int8 deltas, re-based per row for cliffs), VNML, VCLR, up to
  6 texture layers per quadrant from the land-cover classes (Tropical Skyrim textures first, decision 0006 §8),
  through ArgoniaGen and Mutagen.
- **Ground under buildings:** direct landscape edits in the place's cells, owned by the place's layer (old 0102,
  0140). No pads or settle.
- **The piece resolver** (`tools/argonia_world/pieces.py`): an old kit id or mesh path → source plugin and base
  record, read from plugin data (the mined assemblies and registry name the mesh path). A mesh with no base
  record → a new STAT of ours pointing at the mod's mesh. L1: every piece the design uses resolves.
- **The place:** buildings and props as REFRs on that ground, positioned from the design note with the old layout
  as a reference; doors linked to their interiors through the source plugin's load door (old 0114); containers,
  beds, seats and stations as working references. Trees and rocks by region rules.
- **Water:** Skyrim's own (cell water or placed planes, vanilla pieces), tuned with Community Shaders; the old
  water's look is not reproduced.
- **Navmesh:** (a) round-trip one CK navmesh through Mutagen and confirm an NPC walks it (proves the writer);
  (b) generate the block's navmesh by tes4skyrim's method (collision → walkable triangles, door and water flags,
  cross-cell links, NAVI); (c) the CK's generator on the Windows game machine, scripted, as the check and fallback.
- **People (decision 0026 §6):** three Claywater people imported from the old records, with **whole-body
  templates**: each NPC inherits race, head parts, skin, weight and height from one template NPC (TPLT, traits
  flag), never a face alone. Argonian heads are the critical case. If templates cannot cover a unique face, the
  CK's FaceGen export (development and the owner's machine only) and the installer design of decision 0014 §3.
  They get a sandbox package at the place and a sleep package at night.
- **The look loop:** vantage stills through SkyLink, judged by a reader against `claywater-station.design.md`
  with the Nordic-tells checklist; fix and re-shoot until it matches.
- **G4 passes when:** in game, the player walks the road into the place and its interior; ground heights match
  the heightfield within 0.5 m at sampled points away from the place's own edits; NPCs path between two spots
  (no standing still); each person's full-body still shows no seam or tone mismatch and no dark face; every piece
  resolves; the reader passes the stills; regenerating twice gives identical Spriggit output.
- **If it fails:** navmesh or bodies unsolved after (a)–(c) → an owner call with the measured findings.

## S5 → G5: The Morrowind dialogue window (budget 6 days)
- **A minimal window only:** G5 proves the dialogue *engine* and the interception. The window's final
  technology and look come from G11 and 1.2 (decision 0017).
- A minimal view `ui/views/dialogue/` (PrismaUI, the working assumption): NPC text with hyperlinked keywords, a topic list on the right, greeting on
  open, persuasion button, Goodbye; Pelagiad; the old palette; gamepad, mouse and keyboard navigation; tested at
  1920×1080, 1280×720 and the phone's two aspect ratios.
- **Route first: tes4skyrim's MorrowindRuntime** (0.1 §j), a port of OpenMW's dialogue engine and MWScript
  interpreter into SKSE, already doing topics, hyperlinks, disposition, persuasion, the journal and services in
  Skyrim. Fork it or depend on it, with our PrismaUI view in place of its SWF menu and our data compiled to its
  input, if 0.1's audit says that fits. Only the parts it cannot do are built as below.
- ArgoniaCore stub (for what MorrowindRuntime does not cover): on talking to an NPC, intercept vanilla dialogue
  (MorrowindRuntime's vtable swap first; then Enderal's DialogueMenu hook, Dialogue History and Dynamic Dialogue
  Replacer), open the view, supply topics and responses from a small JSON, evaluate
  three condition kinds (disposition ≥ N, knows-topic, quest stage), learn a topic when its keyword is clicked,
  persist the learned set in the SKSE co-save.
- **G5 passes when:** the view passes L3 tests against mock JSON, and in game a topic learned from NPC A appears
  when talking to NPC B; disposition changes which response shows; save/load keeps the learned set; it works
  through the stream with a gamepad.
- **If it fails:** the Skywind approach (topics as Skyrim player prompts gated by conditions in the vanilla menu,
  restyled per 0014 §7) with a written loss of the hyperlink feel, agreed with the owner.

## S7 → G7: Swimmable stepped rivers (budget 4 days)
- In the S4 block, one river reach dropping 4 m over 200 m modelled as Skyrim does: placed water planes or meshes
  stepped along the reach with a small vanilla waterfall/rapids piece at each step (old 0064), plus the cell's own
  water height where the river is flat.
- Check: the player and an NPC swim in each plane; diving and breath work (Underwater NG); no z-fighting at steps.
- **Flow:** Skyrim's flowing water uses a per-water-type flowmap painted in the Creation Kit (one flow worldspace
  per plugin). Try to generate a flowmap ourselves from the reach directions; else accept still water on rivers
  and record the visual loss.
- If submersion on a placed plane misbehaves and records do not explain it, this is the first allowed Ghidra
  question (decision 0010 §4): find how the engine resolves which water a point is in.
- **G7 passes when:** swim checks pass and flow is either generated or its loss recorded. **If it fails:** keep
  rivers flat per cell segment (one water height per cell, terrain re-graded at cell borders) and record the loss.

## S8 → G8: The agentic loop, end to end (budget 3 days)
- A `deliver-small` agent, given only a brief, changes one record (an NPC's greeting), regenerates the plugin,
  deploys it (`make deploy`), runs a check (talk to the NPC, read the response through the bridge), and reports
  pass/fail, without human help.
- **G8 passes when:** the loop runs unattended three times in a row and the median cycle (edit to verdict) is
  under 10 minutes including GPU-box start; cost per cycle is recorded. **This cycle time feeds the
  re-estimate of every later part (PLAN §5).**

## S9 → G9: DS1 timing without shipping edited animations (budget 5 days)
- **Runs only if a tuned window cannot be met by the mods' own settings** (owner ruling 2026-10-28; decision
  0019).
- Decisions 0014 §2 and 0019 §6. First pick, for each of the three actions, the permitted Skyrim clip whose motion
  is already closest to the DSR reference capture; then, on one roll, one straight-sword light attack and one
  shield parry: drive timing at runtime
  (our plugin changes playback speed inside windows through graph variables / Payload Interpreter / AMR and opens
  our i-frame/parry/active windows from animation events), measure with an early version of the 1.4 test dummy.
- If a window cannot be met at runtime, prototype the **install-time patcher**: our annotation/timing delta applied
  to the player's own copy of the clip, never committed or shipped.
- **G9 passes when:** the three actions hit their (G6) windows within ±1 DS1 frame at 60 fps with runtime control,
  or with the patcher, and the method is written into decision 0014. **If it fails:** the owner decides between
  looser timing (recorded deviations) and a different moveset source.

## S10 → G10: Where each rule lives: Skyrim's own systems first (decision 0026)
- **Input:** the goals list (0.1 §f, `docs/design/goals.md`) and the reuse audit (0.1 §j). The old project's rule
  code is goal evidence only; none of it runs here. Combat is its own route: existing mods, tuned, built only where they fall short (decision 0019).
- **The native map** (`docs/research/native-map.md`): for every goal, the Skyrim mechanism that carries it,
  in route order (decision 0010):
  - records and settings: actor values, perks and entry points, magic effects, spells and enchantments,
    factions and crime factions, detection and stealth settings, AI packages and combat styles, encounter zones
    and levelled lists, quests and the journal, barter, game settings;
  - existing tools and mods: tes4skyrim's MorrowindRuntime and TESRuntime, the Nexus mods in PLAN §4;
  - our own SKSE code only for what is left, named with its size.

  Each row says how well the mechanism meets the goal (fully, with a stated loss, or not at all) and why.
- **Prove the three hardest rows in game** (the planner picks them from the map; likely candidates: Morrowind
  attributes driving skills and derived values through actor values and perks; spellmaking and levitation through
  magic effects; vastei and levels at rest). Each gets a small plugin or SKSE stub and an L4 check that can fail.
- **Size what is left:** the SKSE code the map leaves to us, as modules in `skse/core/` (pure C++, no Skyrim
  types, unit-tested at L2, what the core runner calls) and thin Skyrim-facing glue.
- **G10 passes when** every goal has a row with a verdict and evidence, the three hard rows pass in game, and
  every "not at all" row is an owner call. The map sets 1.1 and every system brief's route.
- **If it fails:** a hard row that cannot be met natively moves to our SKSE code, with the cost stated in the
  check-in.

## S11 → G11: The UI approach, chosen with the owner (decision 0017)
Runs on the build VM as a side lane beside the other spikes; only its probes need the game machine. It closes
before 1.2 starts and before G5's window is built beyond a minimal one.
- **Read first:** decision 0017 (the four goals in the owner's order), 0006, 0014 §7; the old `packages/ui` and
  its review notes; OpenMW's window layouts and how its windows drag, resize and persist; the reuse audit's UI
  rows (0.1 §j), MorrowindRuntime's menu included.
- **The study** (`docs/research/ui-approach.md`):
  - the candidates of 0017 §1 and any others found;
  - each scored against the four goals, touch and gamepad on the phone, performance through the stream, how
    many vanilla screens it can replace, the effort to build and maintain, and licence and single-author risk;
  - a short look at what modern Skyrim UI mods and current games do well, with screenshots referenced by link,
    never copied into the repo.
- **Probes in game, one per serious candidate, on the hardest capability:**
  - the pause menu's windows open together over the game, dragged and resized with the mouse, remembered after
    a restart, and usable by pad and touch;
  - a dialogue window holding 300 topics, scrolling and filtering without a hitch.

  Each probe gets an L4 check that can fail, with its frame-time cost.
- **Mock-ups for the owner:** the same three screens (dialogue, the pause menu's windows, the HUD) in two or three
  directions, rendered as stills at desktop and phone sizes, plus the agent's recommendation and why.
- **The owner call** (`owner_inbox.py`, an owner-call issue with the stills): choose the approach and a direction
  to refine. Further rounds on the look happen in 1.2 §a.
- **G11 passes when** the owner has chosen, the probe of the chosen approach passed, and decision 0017 and the
  briefs that name a UI technology are rewritten to match.

## Loops (docs/loops.md)
Each spike is its own focused loop, closed by its gate; the ladder still applies inside a spike (prove at L1–L3
before spending GPU time at L4, and film nothing without a reason).

## Done when
All of G1–G11 pass, or a gate's documented fallback is accepted by the owner in writing; decisions 0001, 0002,
0004, 0007 and 0014 carry the measured facts. The gate evidence (frame times, stills, the stream verdict and
latency sum, golden-table rows, the native map) goes into the Part 0 check-in (README § exit).

## Risks and fallbacks
- **PrismaUI** (single author, restrictive licence) fails or breaks: pin its version in S3; each S3 screen keeps a
  fallback (decision 0001 §2, 0014 §7).
- **Steam offline refresh** interrupts unattended GPU work: the S0 check script and owner re-login step.
- **Windows-only tools** (DSAnimStudio, UXM, the CK) fail under Wine: a temporary Windows spot instance within the
  Part 0 budget, stopped after use.

## Deliberately out of scope
Polishing spike code beyond what 0.3–0.5 adopt; content beyond the samples; combat beyond G9 (1.4, 2.7).
