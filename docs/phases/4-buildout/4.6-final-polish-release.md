# 4.6: Final look, polish and release

**Goal.** The final look, the `P3` queue, the performance lock, and the full public release on Nexus, with the
after-release process running.

**Starting state.** Written by the agent that closes the last packet.

**Read first.** Decisions 0006, 0007, 0015; the backlog's `P3` rows; the 3.4 Outcome.

## Deliverables

### a. Final look: light, fog, volumetrics, water, weather
- Community Shaders presets per region and weather: humid marsh light, volumetric fog and god rays through
  canopy, marsh mist, waterfall mist, rain; water shader tuned for murky fresh water vs sea; image spaces; all
  measured against the 0.2 §d frame-time bar on the chosen instance.
- Use RenderDoc captures on the GPU box (Linux/Proton supports it) for pass order and fog parameters when a look
  question cannot be answered from settings.
- Reference: the old project's look decisions (haze by default, old 0136; light and world time, old 0016; mist
  volumes, old 0124) and its screenshots.
- **Acceptance:** reader panel on a 50-shot vantage set across regions and weathers; owner look packet; frame
  time within the bar.

### b. The P3 queue and the performance lock
- Every `P3 final` row is done, or marked `optional` by the owner.
- **The performance lock:** frame time on the 2.W6 grid plus every place, on the owner's GPU instance and on the
  documented player minimum. Nothing ships under the bar.

### c. Nexus page
- Page text, screenshots (our own captures), requirements list, permissions section (our licences per decision
  0015), AI tags, links to the repo and the release.
- **Owner step:** the owner publishes from their account.
- **Acceptance:** the page draft passes text-review; every requirement links to its source page; the owner
  confirms publication.

### d. After release
- Bug triage process (issue template → planner triage → fix lanes → patch release); runtime-pin moves only by
  decision record; dependency updates only after the full smoke and journeys pass.
- **Acceptance:** the issue template exists; one dry-run bug goes from report to a patch release through the
  process.

## Loops (docs/loops.md)
- **Subsets:** the look per region and weather (L4 vantage stills plus frame time); each `P3` row (its own check); the
  release file list (L1).
- **Journeys:** the whole set, on the dev profile of the installer-built stack (game runner on the Windows test
  machine); the release build is played by the owner.

## Owner check
The look packet; publishing the Nexus page from the owner's account.
