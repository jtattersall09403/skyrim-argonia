# 1.2: The UI foundation: the design system, the HUD and the thread's screens

**Goal.** Our own UI (decision 0017) exists as one design system in the approach G11 chose, with a look the
owner has worked through and approved, in a harness; the HUD runs in game, and
the screens the core loop needs are wired to live state. Every later screen composes these parts, so the whole
game has one visual language by construction.

**Starting state.** Written by the agent that closes 1.1. Expected: the message schema exists; G11 chose the
approach and a direction; G5's minimal dialogue window exists.

**Re-check before starting:** the versions of what G11 chose (PrismaUI, React and Vite if web views; SkyUI
and the SWF tools if Scaleform).

**Read first.** Decision 0017 in full; the G11 study and the owner's choice; 0014 §7–8; the old repo's `packages/ui` README and its 2.2 brief
(`docs/design/phases/2-slice/2.2-ui-system.md`, imported); [source-map.md](../../source-map.md) row for
`packages/ui`.

## Deliverables

### a. The look, with the owner, then the design system (decision 0017 §2)
- **Look rounds with the owner** (owner-call issues with stills, one round at a time):
  1. mood boards in the chosen direction, drawing on modern Skyrim UI mods and current game UI;
  2. the design language: type scale, colour, spacing, window chrome, motion and focus states;
  3. the three hardest screens in it (dialogue, the pause menu's windows, the HUD) at desktop and phone sizes.

  Each round's ruling is written into `ui/DESIGN.md`, the one statement of the language every screen composes.
  The agent stops for each round's answer and works on what does not depend on it meanwhile.
- **The design system** in the approach G11 chose. If it is the old React system in PrismaUI, `ui/` (React 19,
  TypeScript, Vite) adapts the old `packages/ui` to the approved language, starting from its tokens and
  palette (panel #0e1711, trim #6b7744, bone #d6cfb0, health #8f2e22, stamina #2a6b33, magicka #2f4e94, breath
  #386570, marker tan #d8b070, crime #e0705a), components (Window, Deck, List, Tabs, Tip, Bar, Meter, Slider,
  CountPicker, Linked, Items, Overlays, Symbol), the focus model (keyboard/gamepad/touch), the viewport model, CSS,
  and their vitest tests; Pelagiad web font with its OFL licence; only provenance-clean assets (0017 §5: our
  Fal-made symbols and map glyphs, the owner's ChatGPT-made flourishes; Skyrim's symbols extracted at install).
- **Skyrim's own UI symbols** (sneak eye, map pins, button glyphs) are extracted on the installing machine from
  the player's `Skyrim - Interface.bsa` by the ported `extract_symbols.mjs` (decision 0017 §5); the harness
  uses labelled placeholders for them and the L4 sweep checks the real ones.
- Replace old `@elder-souls/game-core` / `text-catalogue` imports with the typed message schema; a mock data
  server feeds the harness; Playwright screenshot tests; keyboard/gamepad navigation tests.
- Views talk to ArgoniaCore only through the 1.1 message schema.
- Viewports: 1920×1080, 1280×720, and the Honor Magic V5's folded (~21:9) and unfolded (near-square) shapes at
  the UI scale chosen in G2; a readability check (minimum rendered text height) in each.
- **The pause menu's windows** (decision 0017 goal 2): open together; on desktop draggable and resizable, with
  positions and sizes remembered per device between sessions (a per-player UI settings file, never the save);
  at the phone shapes and with a pad, the same windows in a fixed layout reached by touch and pad.
- **Acceptance:** the G5 dialogue window moves into the harness and passes; screenshot tests are deterministic;
  window positions survive a restart (L4).


### b. The HUD
- From the old `packages/ui/src/hud/`. It holds:
  - souls-style bars that grow with stats: health, stamina, magicka and breath, plus climb stamina;
  - the belt (quick items), the corners and the crosshair;
  - the sneak eye (four states) and the effect stack;
  - the place-discovered banner, quest notices, the wind mark and the vastei plaque;
  - the floating prompt with input glyphs (keyboard and gamepad).
- There is no compass. Boss bars are drawn by our HUD, with TrueHUD only as a data source if that is cheaper.
- The vanilla HUD and compass are hidden through the 1.1 router.
- Skyrim's own symbols (the sneak eye, map pins, button glyphs) are extracted on the installing machine
  (0017 §5). The harness shows labelled placeholders, and the L4 check shows the real ones.

### c. The thread's screens, wired
- Ported from the old `packages/ui/src/screens/` and wired to ArgoniaCore through the schema:
  - **Dialogue**, with 1.3;
  - **Inventory with paperdoll**, with 1.3: equipped slots drawn as Morrowind's doll, filters, weight and burden;
  - **Container** and **Reader** (books and notes), with 1.3;
  - **Stats**, the sheet, with 1.3;
  - **LevelUp**, the sitting, with 1.5;
  - **Death and Rest**, with 1.5;
  - **WindCall**, with 1.7.
- Windows are free on desktop (above) and become full-screen pages at the phone shapes. Each
  screen's old tests move with it.
- Every other old screen is ported into the harness only (L3, mock data), so 2.2 starts from a complete set.
- **Pelagiad** in every view (the web font). Any vanilla text still showing uses our font library SWF and
  `fontconfig.txt` (0014 §7), built here.

## Acceptance
- Each ported screen passes its old tests and L3 stills at the four viewports, judged by a reader.
- In game, every wired screen opens from the player's own action, shows live state, and closes back to play.
- The vanilla screen it replaces cannot be opened.
- The HUD's states show at L4 (a still per state).
- Text is readable on the folded Magic V5 at the G2 scale: the minimum rendered text height is met.

## Loops (docs/loops.md)
- **Subsets:** each screen (L3 four viewports, L4 open/close); the HUD states (L3, L4); fonts (L4 still of any
  remaining vanilla text).
- **Joins owned:** the gameplay ↔ screen hand-off for each wired screen: no vanilla flash, focus kept, no input
  eaten. This is **L5, reason: a hand-off shows only in motion**, one 3–8 s clip per screen, read by a reader.
- **Journeys:** none of its own; screens are steps in 1.7's journey.

## Owner check
The look rounds in §a. The screens in play: in 1.7.

## Deliberately out of scope
