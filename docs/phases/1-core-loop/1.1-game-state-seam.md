## Deliverables

### a. ArgoniaCore and where the rules live
- **First, the native map** (`docs/research/native-map.md`; decision 0026): for every goal in
  `docs/design/goals.md`, the Skyrim mechanism that carries it, in route order (0010): records and settings
  (actor values, perks and entry points, magic effects, factions, detection, AI packages, encounter zones, quests,
  barter, game settings); existing tools and mods (the reuse audit's rows; tes4skyrim's runtimes); our own SKSE
  code only for what is left, named with its size. Each row says how well the mechanism meets the goal (fully, with
  a stated loss, or not at all) and why; a "not at all" row is an owner call. **The rows Part 1 needs are proved in
  game first**, each with a stub and an L4 check that can fail: the sheet's attributes driving skills and derived
  values through actor values and perks; vastei and levels at rest; quests as records with ArgoniaCore conditions.
  The rows for later systems are mapped on paper and proved by their Part 2 chunk.
- `skse/ArgoniaCore`: the SKSE plugin that owns all new state. The state covers attributes, skills beyond
  vanilla, vastei, pending levels, learned topics, dispositions, the Owing ledger, knowledge facts, the journal
  log, discovered places, item condition and boat ownership.
- **Rules live where 1.1 §a's native map put them** (decision 0026):
  - Skyrim's own records and settings, generated by the pipeline, carry everything the map gave them;
  - the tools and mods the map chose are dependencies;
  - what is left is our code in `skse/core/` (pure C++, no Skyrim types), written fresh for this engine and
    never ported from the old packages. It is unit-tested at L2 on the build VM, and the unit tests are its proof.
- **Logic out of Papyrus.** Papyrus is used only for quest-stage fragments and glue the engine requires. Its VM is
  slow and latent under load, and its saved script state is the classic source of save bloat. Every Papyrus
  script we ship is listed with why it is not C++.

### b. The save contract
- One SKSE co-save. Each system registers a **save family**: an id, a schema version, `save()`, `load()`,
  `migrate(from)` and `reset()`. Families are added as systems land, never by editing another's.
- Versioned from day one. Loading an older family runs its migrations, and a family with no migration for an old
  version refuses the load with a readable message, never a silent corruption.
- `reset()` is what the studio calls when it applies a scene in place (0.4 risk fallback). It is tested by a
  before/after state read.
- The suspend save: a hidden save on quit and on stream drop, used only to resume. It is not a player save
  (rest is the only save, 1.5).
- **The L2 round trip:** save → load → compare for every family, generated from each family's schema.

### c. The message schema
- `ui/schema/*.ts` is the one source of the typed JSON messages between ArgoniaCore and the views (state pushed
  to views, intents sent from views). Its C++ twin is generated from it. A message not in the schema is
  refused at both ends.
- Views never hold game state. They render what ArgoniaCore sends and send intents back.

### d. The menu router and interception points
- One registry of every vanilla surface we take over, with what replaces it. A surface is a menu, the dialogue
  menu, death, level-up, the HUD or a notification; it can be replaced by our view, suppressed, or restyled.
  It is filled as each system lands, and it is the source the 2.2 UI map and the immersion inventory read.
- The hooks are installed once, here: menu open/close events, the dialogue-menu intercept (1.3 §b), the death
  intercept (the Respawn – Soulslike pattern), and level-up and XP suppression. Each later system registers a
  handler; none installs its own hook.

### e. Records for systems
- Every new record type a system adds follows the data rules: one home table under `world/` or `data/`, stable
  ids, references by id, an L1 integrity rule, and a `docs/design/world/98-data-model.md` update in the same
  change.

  (L4).
- **Joins owned:** studio scene → reset → family state (L4).
- **Journey:** save–quit–load.
