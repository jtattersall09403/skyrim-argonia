# Part 1: The core loop on one place

**Goal.** One thin thread through every system that is risky on this host, on one real place, played by the owner in the studio, so that
two things are known before the world and the systems are built at scale:
- that every system can **join** on this host (the mod stack, our plugins, the PrismaUI views, the co-save and
  the quarantine, all at once, with no crash and no script lag);
- that **DS1 combat feels right** through the stream.

The place is **Claywater Station** and its 8×8-cell block (built in 0.2 G4, regenerated by 0.5), plus the
proving ground. The exit is the owner's verdict in 1.7, the last cheap moment to change host (decision 0001's
fallback is OpenMW; decision 0023 §1).

**The thread.** Each system gets its **first rung at its final interface**: the real records, the real co-save
family, the real view and the real formulas. Part 2 deepens each one and never replaces it (decision 0023 §2):

| Verb | First rung here | Made whole in |
|---|---|---|
| talk | three Claywater people with their imported lines: greeting, hyperlinked topics, disposition bands, Goodbye | 2.5 |
| carry, equip, read | one weapon class, one armour set in Morrowind slots, a container, a book; burden tiers | 2.3 |
| fight | straight sword, rolls per burden tier, guard, parry, riposte, backstab, poise, against one DS1-mirrored archetype, measured from DSR | 2.7 |
| grow | skill use in anger → vastei → a pending level → rest → the sitting | 2.8 |
| die | wake at the last rest; the vastei pile; take it back | 2.8 |
| save | rest is the only save; the suspend save; a save/load round trip of every family | 2.17 |
| move | climb a cliff and the proving-ground walls; swim and dive with breath; a ladder; sail one boat 200 m and moor it | 2.13, 2.15 |

**What is left out on purpose.** Barter (2.6) and quests with the journal (2.12) are not in the thread: both are
well-trodden in Skyrim modding (quests generated from records took one universal-modder port about 30 builds,
solvable but not a host risk), so testing them here would cost time without changing the verdict. The thread
keeps what could make the host fail: dialogue interception, the UI taking over vanilla screens, DS1 combat through
the stream, the Souls death-and-rest loop on the co-save, and climbing, swimming and boats.

**What this part is not.** It does not build breadth: no second weapon class, no magic school, no crafting
station beyond what the thread needs. A gap found here that needs a whole system is noted in that system's
Part 2 brief, never built now.

## Part 1 exit (the owner signs)

- The core-loop journey (1.7) is green on both runners, twice in a row, and the stack ran a 60-minute soak
  (the journey looped) with no crash, no growing script lag (the Papyrus queue length is read through the
  bridge) and no co-save growth beyond the expected.
- The owner played the thread in the studio and gave the verdict, with the measured stream latency written
  beside it:
  - **Combat:** does it feel like Dark Souls?
  - **Dialogue:** does the window feel like Morrowind?
  - **The UI:** is it one coherent UI?
  - **The game:** is this the game you want?
- A **yes** opens Part 2. A **no** on combat or the host triggers decision 0001's re-plan: a written comparison of
  fixing it here against moving to the fallback, costed.
- The planner re-estimates Parts 2–4 from Part 1's measured cycle times.
