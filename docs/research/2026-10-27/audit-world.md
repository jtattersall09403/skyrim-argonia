## 3. What ports to OpenMW records and what does not
Ports cleanly (data in, records out via a new exporter; tes3conv JSON is the target):
- Terrain heightfield: frozen f32 arrays heightfield-sculpted/shaped/refined-height-frozen-f32.npy (hashes in world/sources/terrain/freeze.json), 4033x4033 at 1.828 m, true metres, plus patches (terrain-patches.json, route-grade-patches.json). Live in the vault (ELDER_SOULS_ASSET_ROOT, "../elder-scrolls-asset-pipeline" per CLAUDE.md; sibling dir /home/claude/elder-souls-argonia/../ contains only this repo, so the vault is NOT present in this environment - unverified). Browser rasters in apps/world-studio/public/province/ (height16.png, height-rg.png, hydro-*.png, chunks/, apron/). Maps 1:1 to Morrowind LAND (65x65, 128 u). Issues: LAND vertex heights are quantised delta int8*8 units (max ~14.5 m per vertex step), 650 m summits are 45,500 units (fine); landscape textures (LTEX) must be re-mapped from the splat palette (hydro-soil, land-cover classes, 40-60 texture library, 20-province-design s16) to LTEX/VTEX painting.
- Place catalogue (827 ids with position {u,v}, positionM, danger tier, culture, sitingPrefs, lootTable, relations): maps to cell names/ REFR groups and region records. Stable ids `place.<region>.<slug>` map to editor ids.
- Registries: factions (32) -> FACT records with ranks; items (508), creatures (42), NPCs (959) -> NPC_/CREA/CLAS/FACT/INGR/MISC; creature statblocks use fixed bands D1-D5 (not levelled lists - good fit, OpenMW can use fixed leveled=none).
- Quests: stage graphs (id 10,20,.. onEnter actions, objectives, successors, failForward, ending) are structurally the same as INFO journal entries with index; journal/objective text per stage maps to journal INFO records (text keyed text.journal.<code>.<stage>). Topics (`topic.*`, 317) and per-NPC overrides map to DIAL/INFO with speaker filters.
- Written text: world/sources/text, dialogue lines (words + low/high variants map to disposition-filtered INFO), glossary (96), books/letters (documents.json).
- Weather/climate/calendar: climate/weather-states.json, sky/star-catalogue.json (13 Patrons, Serpent): port as region WTHR + Lua clock.

Needs translation work or does not port directly:
- Condition vocabulary (docs/quests/85-condition-vocabulary.md): ~50 predicates in A1-A8, 40 actions B1-B5. Mapping: questStage->getJournalIndex, hasItem, skill/attribute thresholds, faction rank/reputation, dispositionAtLeast, inRegion/inCell, flag/counter->global/local variables; timeOfDay/calendar->GameHour/Day/Month globals. No equivalent without Lua: knowsTopic/topicHeardFrom (Morrowind topics have no "heard from whom" state), witnessed, evidenceState, custody, owingAtLeast (crime as per-region ledger; Morrowind has bounty), rumourActive, settlementStanding, seenBy/detection service, successorActive, placeStanceIs, localVariantActive, applyLocalVariant/enableRef/disableRef/moveRef (OpenMW Lua: object:enable/disable/teleport OK), setSchedule, setWeather per location (Lua OK), no-dice persuasion (Morrowind persuasion is a roll-free Speechcraft formula - fine). Per the quest doc "No dice anywhere"; OpenMW dialogue filters also support only a fixed predicate set, so those predicates need the Lua layer (a runtime reimplementation of packages/narrative and packages/dialogue).
- Dialogue "walk" gates (disposition 0 essential topics, culture-chain speakerCulture, pool/override derivation) - these are generated at build time and could be flattened to per-NPC INFO records (Morrowind filters by NPC id, race, class, faction, rank, cell, disposition, PC faction...). A flattening exporter is needed. ~1,471 lines + 569 pool entries.
- NPC schedules and sockets: socket vocabulary (world/sources/vocab/socket-vocabulary.json: socketKinds npc/idle/item/container/station/sign/encounter/fauna/ambience/marker/plant/mooring; dayPhases night..dusk; schedulePurposes work/home/evening/leisure; activities stand,sit,sleep,lean,work-at,fish,tend,cook,pole) and NPC day blocks ({from,to,spot,activity}, registries/npcs.json) have no Morrowind record equivalent; Morrowind has only AI packages (Wander/Travel/Follow/Escort/Activate) and OpenMW 0.49+ Lua needed for sit/sleep/work animations and schedules. Sockets become object refs with a Lua script reading a data table. Local-state overlay (per-save variants) = Lua storage.
- Places: blueprint layouts are 3D poses of Skyrim kit pieces (layout.json "ops" - e.g. greenspring 444 ops) over the frozen terrain, with per-place ground patches ("a place carries its own ground", decision 0102; building pads with retaining walls, 0101). The geometry is useful as REFR transforms but every assetRef is a Skyrim/mod mesh. In OpenMW terms these are cells' REFR lists, convertible only if the underlying meshes become available as NIF in OpenMW (Skyrim NIFs v20.2.0.7 / BSTriShape are NOT loaded by OpenMW; need conversion). Placement rules 97-placement-principles.md (74 KB) and the playbook are design knowledge, not data - reusable as rules for a new generator.
- Interiors: decision 0114 binds a shell to an interior cell only via the plugin's own load door (world/sources/placement/exterior-interior-links.json, 38 kit-interiors) - this links Skyrim plugin CELL/REFR data; it would have to be re-expressed as OpenMW door->cell teleports (Morrowind DOOR destination data are straightforward: XTEL). Port is plausible if the interior cells themselves (Skyrim ESP CELLs) are converted; otherwise redo.
- Water: world/sources/hydrology/hydrology-graph.json (101 rivers, 615 reaches, 202 junctions, 2,280 bodies, schema v1) + authored-bodies, approved-bodies, water-corrections. Morrowind/OpenMW exterior water = ONE water height per cell (CELL WHGT); rivers falling in slope, tidal state, flood seasons, rapids, current fields, swim-depth/oxygen need per-cell stepping or custom water meshes. Terrain is carved to the hydrology graph (trenches, weirs, plunge bowls), so a cell-level water height will be wrong in many cells. This is the biggest structural mismatch (rendering and swim code in docs/world/60-water-traversal.md assume continuous water fields, compiled water-fields.ktx2). Flood state/season, tide (flavour only; gating cut, 0042) are runtime.
- Routes: world/sources/routes/*.json (travel services, harbour stations, rootworm stations, junctions) - map to Morrowind-style travel NPCs (silt strider/ boat) plus dock NPC records; rootworm "Underground Express" is a transport mechanism needing Lua.
- Boats (placement/boats.json, 2.15), climbing, deep diving, Argonian breath etc.: gameplay Lua + animation, not content data (other strands).
- Vegetation scatter (flora/, groundcover-rules.json, 5.7 MB flora data): Instanced scatter rules -> static REFR lists, OpenMW has no instancing; at 63x63 cells with dense jungle this can exceed OpenMW object budgets (not measured).
- Navmesh/nav-*.bin bakes: OpenMW has its own Recast nav; the bakes are not reusable.
- Skyrim-specific dependencies flagged: Skyrim.esm record schemas (leveled lists read as a checklist only), vanilla meshes named in the socket vocabulary (e.g. `vanilla:meshes/clutter/food (bread01a)`), the Skyrim humanoid rig and animations (tooling/asset-pipeline/output/rig-skyrim-humanoid.animations.json, races.json), Skyrim "Tamriel Worldspaces - Argonia" ESP as the terrain origin (world/sources/README.md; vault mod-sources/tamriel-worldspaces-118678), Transbot9 apron heightmap (CC BY-NC 4.0), Skyrim sneak/detection model (lore/topics/skyrim-sneak-detection.md), Skyrim 4096-unit cell constant in scale.py. The world's source of truth is Python tooling in tooling/world-generation and the vault, not the browser app.

## Recommendations
1. Treat repo's world/sources JSON (catalogue, registries, quests, dialogue, hydrology, routes, terrain freeze) as the content spec; the heightfield (1.828 m, 4033^2) is already Morrowind-LAND-aligned (3969 cells).
2. Decide early how rivers/lakes map to per-cell water height (the highest-risk mismatch) and how quest predicates beyond Morrowind's filter set are to be run in Lua.
3. Authored content is small relative to the plan (38 staged quests, ~20 built places of 827, 89 voiced people); the port will be mostly new authoring on top of generators.
