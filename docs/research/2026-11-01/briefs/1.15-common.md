## The contract between the lanes (fixed here so lanes build in parallel)

The world database (`world/schema.sql`, only through `tools/argonia_world/db.py`; records and YAML are derived)
gains these tables. The water lane creates them in its first commit (within the hour) and every other lane
builds against them, with a small fixture while they are empty.

```
cell_water(cx INT, cy INT, level_m REAL, water_type TEXT CHECK IN ('sea','brackish','blackwater','fresh'),
           body_id TEXT NULL REFERENCES hydrology_body, reach_id TEXT NULL REFERENCES hydrology_reach,
           PRIMARY KEY (cx, cy))                       -- one level per cell; a cell absent has no water
water_step(cx INT, cy INT, edge TEXT CHECK IN ('n','e','s','w'), upper_m REAL, lower_m REAL,
           cross_lo INT, cross_hi INT,                  -- the channel's vertex range along the edge (0..32)
           chain TEXT,                                  -- the piece chain id (water/steps.py), or 'closed'
           PRIMARY KEY (cx, cy, edge))                  -- the drop from (cx,cy) across edge to its neighbour
hydrology_reach.cell_kind TEXT CHECK IN ('water','dry')  -- 'dry' = a dressed dry gully (bed pieces, no water)
entrance_site(place_id TEXT PRIMARY KEY REFERENCES place, shape TEXT CHECK IN ('mound','bank','depression',
           'flat','deep_water'), x_m REAL, y_m REAL, radius_m REAL, facing_deg REAL, request TEXT)
region_mist(land_region_id TEXT PRIMARY KEY REFERENCES land_region, regime TEXT CHECK IN ('radiation','sea_fog',
           'montane','none'), hours TEXT, why TEXT)
```

Python API, importable by every lane: `tools/argonia_world/water/solve.py` exposes
`load(db) -> CellWater` with `level(cx, cy) -> float | None`, `type(cx, cy)`, `steps() -> list[Step]`, and
`nearest_level(cx, cy) -> float` (the level of the nearest water cell, for "height above local water").
Ground heights are a float32 (4033, 4033) metres array, row 0 north, as `terrain/grid.py` defines (`Sources.ground`);
the ground lane writes it to `out/terrain/ground-f32.npy` and `Sources.load()` reads it when present.

Skyrim unit facts live only in `tools/argonia_world/skyrim_units.py`.

## How every lane works

- **Golden rule (decision 0034, owner 2026-11-01):** before any rule of yours, ask what you are trying to
  achieve, whether Skyrim's builders faced the same problem, and how they solved it; measure it in
  `/home/ubuntu/games/skyrimse/Data/Skyrim.esm` (readable here with `tools/argonia_world/terrain/esm.py`) and do
  the same. The river-step rule (options §11) is the model. Your report names each such measurement.

- **Worktree.** `tooling/worktree.sh ~/wt-1.15-<lane>`; work there; the main tree is the planner's.
- **Shell through rtk** (CLAUDE.md). No `sleep`, no polling; long jobs under `tooling/job_guard.sh run <name> -- ...`
  and `job_guard.sh wait <name>`.
- **No game machine.** Lanes prove at L1 (data), L2 (unit tests) and L3 (off-game renders read by a `reader`
  agent). In-game checks are journeys the planner runs in one batch of the round. Never start a machine.
- **Lore grounding (0032).** Every relief, water, material, light or flora call cites a dossier
  (`world/sources/lore/`, `world/sources/lore/regions/`), the design doc (`docs/design/world/`) or the imported
  research (`docs/design/research/world-terrain/`, `rendering/`, `vegetation/`) by path, in a comment or a `why`
  column. "Not in the repo" only after `world/IMPORTED_FROM.md`.
- **Reuse first (0010):** data, then a dependency mod's own records and meshes, then our Python; never a
  vanilla asset the player meets unreviewed (0012); never a game file in the repo (0003).
- **Fast loops (0021):** every check at its cheapest level; measure everything, diagnose all, fix once,
  re-measure. L3 renders go to a `reader` agent with the checklist; keep only its verdict lines. Never Read an
  image into your own context.
- **Records in the same commit:** `make check` green (`records`, `ledger`, `world`, `unit`, `lint`); rebase on
  origin/main and push to main as you go (small commits, often: other lanes build on yours). Change only your
  own rows in `docs/phases/1-core-loop/checks.md`; the brief's Status line is the planner's.
- **Scope.** Stay in your Paths. A finding that changes another lane's scope goes in your report, not their files.
- **Return ≤ 25 lines**; the full report at your Report path, rewritten in place, with a **Starting state**
  hand-off (done, diagnosed with causes, owed) at the end of every session. At ~230k context: commit what is
  green, write the hand-off, return.
- **Performance budget:** the build VM has 4 CPUs and 15 GB; the whole province (15,876 cells, a 4033² grid) is
  streamed in row windows with memory-mapped arrays (`terrain/grid.py`); nothing whole-grid in Python loops;
  vectorised numpy only. Measure the time and write it in the report.
