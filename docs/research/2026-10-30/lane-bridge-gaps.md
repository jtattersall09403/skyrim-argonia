# Lane bridge-gaps (2026-10-30)

Goal: unblock the `owed:` steps of the newly runnable journeys (lane-journeys-ready, "Gaps"). Test level L2; the L4
proof is game-13's next slot. Nothing was deployed and no game was launched.

## What was built (skse/ArgoniaBridge, dev-only; nothing in ArgoniaCore)

| Gap | Bridge piece | How |
|---|---|---|
| SetAttribute clamps; novice/god builds | `dev-set SetAttribute <attr> <n>`, `dev-set SetVastei <n>` | ArgoniaCore's own Papyrus natives called by `VirtualMachine::DispatchStaticCall`; returns the stored value. Whitelist in `protocol/dev.cpp` (any other native refused) |
| Pending level for grow-at-rest | `dev-grow <ref> <n> [max]` | hit events (`TESHitEvent`, target's health lowered 20 first so HealthWatch sees damage) sent into ArgoniaCore's own hit sink, until `GetPendingLevels >= n`; returns the blow count |
| Sitting state | none needed | rest at the camp opens it; `core ViewIntent` buys/dones (already whitelisted) |
| TDM lock target | `tdm-target` | TDM's `RequestPluginAPI` (interface V1: movement state, lock state, current target) |
| Vastei pile count | `refs <base> [radius]` | form-map scan, count and enabled count |
| INI compass / markers | `ini <name:Section>` | INIPrefSettingCollection, then INISettingCollection |
| i-frame trace | `trace start <frames> [graph bools]`, `trace read [samples]` | per-frame sample in the player's update hook: pos, health, IsGhost or any named bool; first/last i-frame frame, window ms |
| Land texture | `ltex` | `TES::GetLandTexture(player pos)` |
| Community Shaders | `logfile <name> <text>` | the log is written at launch, so read whole: `CommunityShaders`, "[Interior Sun] Installed hooks" (seen in the machine's log) |

Save loads: `on_main_thread` now waits up to 10 s more while SKSE's kPreLoadGame..kPostLoadGame bracket is open
(answer still inside bridge.py's 15 s cap). A coc load sends no such message and is not covered.

bridge.py (coordinator request): reads that meet "main thread did not run the task" or a connection reset are retried,
3 tries, 0.5/1 s apart, logged to stderr, counted (`transport_retries` per step in run_journey, per item and in total
in run_batch's summary). Writes (`console`, `teleport`, `pad`, `load`, `save`, `dev-*`, ...) are never retried: a
timed-out task stays queued and runs later, so a retry could apply it twice. Assertions and other refusals never retry.
